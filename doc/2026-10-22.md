## 중요한 내용과 코드 흐름

### 병렬 실행과 결과 병합

- `LG/lg09_병렬실행_병합2_concat.py`는 `START`에서 `search`, `analysis`로 각각 엣지를 연결한다. 두 노드가 `search_result`, `analysis_result`라는 서로 다른 상태 키에 결과를 기록하고, 두 결과가 모이면 `merge`가 문자열로 연결해 assistant 메시지에 추가한다.
- `LG/lg09_병합실행_병합3.py`에서는 같은 병렬 구조를 사용하지만 `merge_agent`가 검색·분석 결과를 프롬프트에 넣어 `llm.invoke()`를 호출한다. 따라서 최종 결과를 단순 연결하는 대신 모델이 종합해 작성하도록 설계했다.
- 그래프의 기본 흐름은 `START → (search와 analysis 병렬) → merge → END`이다. 병렬로 시작해도 `merge`가 두 상태 키를 읽으므로 각각의 결과가 준비되어야 한다.
- 두 파일 모두 마지막 그래프 PNG 생성·표시 코드가 있으나, 실제 네트워크·모델·GUI 실행은 검증하지 않았다. `InMemorySaver` import는 있지만 두 코드의 `compile()`에는 checkpointer를 전달하지 않는다. 이 코드만으로 대화 기억이 저장된다고 보면 안 된다.

### 트리 모델과 특징 중요도

- `ml/ml01_feature_importtances01.py`는 Iris 분류 데이터에서 Decision Tree, Random Forest, Gradient Boosting, XGBoost 분류 모델을 만들고, 같은 train/test 분할로 차례로 `fit()`과 `score()`를 수행한다.
- `ml/ml01_feature_importtances02.py`는 Diabetes 회귀 데이터에 네 가지 대응 회귀 모델을 적용한다. 분류의 정확도와 달리 회귀 모델의 `.score()`는 보통 R²를 반환한다. R²가 높을수록 기준 예측보다 잘 맞았다는 뜻이지만, 숫자 하나만으로 모든 품질을 판단하지는 않는다.
- `train_test_split`은 입력 X와 정답 y를 학습용·평가용으로 나눈다. Iris 분류 예제는 `stratify=y`로 각 클래스 비율을 나누기 전과 비슷하게 유지한다. 회귀 예제에는 `stratify`를 사용하지 않았다.
- 트리 모델의 `feature_importances_`는 모델이 분할에 사용한 특징의 상대적 중요도 점수다. 이 이름이 곧 F1-score를 뜻하지 않는다. F1-score는 분류 예측을 평가하는 별도 지표다.
- `ml/ml01_feature_importtances03.py`는 XGBoost 분류기의 `feature_importances_`와 `get_booster().get_score(importance_type=gain)`를 함께 출력한다. 이 코드 주석의 `F 스코어`라는 표현을 통계의 F-score나 분류의 F1-score와 혼동하지 않도록 주의한다. `gain`은 분할이 손실을 얼마나 줄였는지를 기준으로 한 중요도 값이다.
- `ml/ml01_feature_importtances04_그래프.py`는 `plot_importance(..., importance_type=gain)`으로 gain 중요도를 그리도록 구성했다. `plt.show()`는 주석 처리되어 있어 현재 파일만 실행해도 그래프 창이 표시된다고 단정할 수 없다.

## shape와 쉬운 예시

- Iris 데이터의 주석상 `x.shape`는 `(150, 4)`, `y.shape`는 `(150,)`이다. 150개의 꽃 샘플 각각에 특징 4개가 있고, 샘플마다 정답 하나가 있다는 뜻이다.
- 학습/평가 분할 뒤에도 X와 y는 같은 샘플 순서·개수끼리 짝을 이룬다. X의 한 행은 y의 같은 위치 정답과 한 쌍이다.
- 특징 중요도는 시험 문제에서 어떤 단서가 모델의 나무 갈림길에 자주·유용하게 쓰였는지를 점수로 보는 것과 비슷하다. 점수가 크다고 그 특징이 원인이라고 증명되는 것은 아니며, 데이터·모델에 따른 상대적 값이다.
- `gain`은 나무의 갈림길이 예측 실수를 얼마나 줄였는지를 합산·평균하는 관점이다. `weight`는 갈림에 사용된 횟수 관점이므로 두 값은 같은 순위가 아닐 수 있다.

## 반드시 기억할 점

- 병렬 노드는 서로 다른 상태 키에 결과를 저장하고, 합치는 노드는 그 키를 정확히 읽는다.
- 문자열 이어 붙이기와 LLM에게 종합을 요청하는 것은 서로 다른 병합 방식이다.
- `feature_importances_`, XGBoost의 `gain`, 분류 지표 F1은 이름이 비슷하게 언급되어도 서로 다른 개념이다.
- 분류와 회귀는 같은 모델 API의 `.score()`라도 의미가 다를 수 있다. 해당 estimator의 점수 정의를 확인한다.
- `stratify`는 분류 정답 클래스의 비율을 분할에 반영할 때 사용한다.
- 코드 주석의 예상 출력은 이번 실행에서 얻은 결과와 구분한다.
