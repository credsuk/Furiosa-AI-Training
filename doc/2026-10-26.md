## 1. 합성곱은 작은 창문을 밀면서 본다 (`keras2/keras63_sparse1_minist.py`)

`Conv2D(64, (3,3))`은 3×3 크기 창문(필터)을 그림 위에서 한 칸씩 밀며 "이 근처에 선이 있는지"를 확인합니다. 창문이 그림 밖으로 나가면 계산할 수 없으므로, 가장자리에서 한 칸씩 못 미칩니다.

- 공식: `출력 = 입력 - 필터 + 1` (padding을 쓰지 않을 때, `padding='valid'`)
- 28 → 26 → 24 → 23 → 22 → 21 → 20 → 16, 마지막 채널은 필터 개수(8)

실제로 모델을 만들어 층마다 출력 모양을 찍어 보니 다음과 같았습니다.

| 층 | 출력 모양 |
|---|---|
| `Conv2D(64,(3,3))` | `(None, 26, 26, 64)` |
| `Conv2D(32,(3,3))` | `(None, 24, 24, 32)` |
| `Dropout(0.2)` | `(None, 24, 24, 32)` |
| `Conv2D(32,(2,2))` | `(None, 23, 23, 32)` |
| `Conv2D(16,(2,2))` | `(None, 22, 22, 16)` |
| `Conv2D(16,(2,2))` | `(None, 21, 21, 16)` |
| `Conv2D(16,(2,2))` | `(None, 20, 20, 16)` |
| `Conv2D(8,(5,5))` | `(None, 16, 16, 8)` |
| `GlobalAveragePooling2D()` | `(None, 8)` |
| `Dense(8)` → `Dense(16)` → `Dense(10, softmax)` | `(None, 10)` |

- `Dropout`은 모양을 바꾸지 않습니다. 일부 값을 0으로 잠깐 꺼 두는 층이라 칸 수가 그대로입니다.
- `GlobalAveragePooling2D`는 `(16,16,8)`을 **채널마다 평균** 내어 `(8,)`로 만듭니다. 그래서 뒤에 `Flatten` 없이 `Dense`를 붙일 수 있습니다. (이 파일은 `Flatten`을 import만 하고 쓰지 않습니다.)
- 이 모델의 전체 파라미터 수는 **30,970개**였습니다.

## 2. 정답이 "숫자 하나"면 sparse, "원-핫"이면 categorical (`keras2/keras63_sparse1_minist.py`, `keras63_sparse3_cifar10.py`)

주석에 `sparse_을 넣으면 y값이 OneHot을 할 필요가 없다`고 적혀 있는데, 이 말이 정확히 맞습니다.

- `mnist.load_data()`의 `y_train`은 `(60000,)`이고 값은 `0~9` 정수입니다. 숫자 하나가 곧 정답이므로 `sparse_categorical_crossentropy`를 씁니다.
- `categorical_crossentropy`는 정답이 `(60000, 10)` 원-핫이어야 합니다. 정수 라벨을 그대로 넣으면 실제로 `ValueError: Shapes (None, 1) and (None, 10) are incompatible`가 납니다. (Keras가 정수 라벨을 `(N,1)`로 해석해 출력 10칸과 맞지 않는다고 알려 주는 것입니다.)
- 반대로 `cifar10.load_data()`의 `y_train`은 **`(50000, 1)`** 입니다. mnist와 달리 한 겹 더 감싸여 있습니다. 이때도 sparse 손실은 그대로 동작합니다. 실제로 같은 데이터를 `(20,)`과 `(20,1)`로 각각 넣어 손실을 계산해 보니 둘 다 `2.46096`으로 같았습니다(Keras가 마지막 축 1을 눌러서 맞춰 줌).
- 다만 **한 모델 안에서 1차원 → 2차원으로 섞어 쓰면** keras 2.15에서 `TypeError: '>' not supported between instances of 'NoneType' and 'int'`가 났습니다(`sparse_categorical_accuracy` 지표가 모양을 추론하다 실패). 안전하게 `y_train.reshape(-1)`로 1차원으로 맞춰 두는 편이 좋습니다.

## 3. `predict` 결과는 점수표, `argmax`로 답을 고른다

```python
y_predict = model.predict(x_test)          # (10000, 10) : 10000장 × 10개 클래스 점수
y_predict = np.argmax(y_predict, axis=1)   # (10000,)    : 장마다 가장 큰 점수의 위치
```

- 실제로 10000장을 예측해 보니 `predict` 결과는 `(10000, 10)`, `argmax(axis=1)` 후에는 `(10000,)`이었습니다. `y_test`도 `(10000,)`이라 짝이 맞습니다.
- `axis=1`은 **행마다** 최댓값 위치를 찾습니다(그림 한 장 안에서 10개 점수 중 최고). `axis=0`은 **열마다** 찾으므로 `(10000,10)`이면 결과가 `(10,)`이 됩니다. 숫자 10개가 나오지만 이는 "클래스별 우승 횟수"가 아니라 "각 클래스에서 가장 높은 점수가 몇 번째 그림이었나"라는 전혀 다른 값입니다.
- 손으로 확인하는 작은 예: `[[0.1, 0.7, 0.2], [0.6, 0.3, 0.1]]`에서 `axis=1`은 `[1, 0]`(첫 행 2번째, 둘째 행 1번째), `axis=0`은 `[1, 0, 0]`입니다.
- `softmax`의 출력은 행마다 합이 1입니다. 실제로 확인한 최대 오차는 `2.4e-07`로 사실상 1.0이었습니다.

## 4. `Reshape`는 "숫자 개수"만 맞으면 모양을 바꾼다 (`keras2/keras65_Reshape1.py`, `Reshape2.py`)

`Reshape1`은 전처리에서 하던 4차원 변환을 **모델 안에서** 합니다.

```python
model.add(Dense(280, input_shape=(28,28)))   # (N, 28, 28) -> (N, 28, 280)
model.add(Reshape(target_shape=(28, 28, 10)))  # (N, 28, 280) -> (N, 28, 28, 10)
```

- 왜 될까요? 한 장(샘플)의 숫자 개수를 세어 보면 `28 × 280 = 7,840`, 바꾼 뒤에는 `28 × 28 × 10 = 7,840`으로 **똑같기** 때문입니다. `Reshape`는 값을 새로 만들지 않고 나열 순서만 바꿔 담습니다.
- 일부러 개수를 맞지 않게 `Reshape(target_shape=(28,28,9))`로 해 보니 `ValueError: total size of new array must be unchanged, input_shape = [28, 280], output_shape = [28, 28, 9]`가 났습니다.
- `Dense(280)`은 "Reshape를 하기 위한 준비"입니다. 이 층에는 가중치가 있어서(`28×280 + 280 = 8,120개`) 성능이 좋아질 수도 나빠질 수도 있습니다.

`Reshape2`는 반대로 **Conv2D → LSTM**으로 넘어갈 때 씁니다. 실제 출력 모양은 다음과 같습니다.

| 층 | 출력 모양 |
|---|---|
| `Reshape((28,28,1), input_shape=(28,28))` | `(None, 28, 28, 1)` |
| `Conv2D(64,(3,3))` | `(None, 26, 26, 64)` |
| `Conv2D(32,(3,3))` | `(None, 24, 24, 32)` |
| `Conv2D(16,(2,2))` | `(None, 23, 23, 16)` |
| `Reshape((23*23, 16))` | `(None, 529, 16)` |
| `LSTM(10)` | `(None, 10)` |
| `Dense(16)` → `Dense(10, softmax)` | `(None, 10)` |

- `(23, 23, 16)`을 `(529, 16)`으로 바꾸는 이유: LSTM은 "시간의 흐름"을 따라 읽는 층이라 `(개수, 시간, 특징)` 3차원을 받습니다. 여기서는 **529개 위치를 시간으로**, **16개 채널을 특징으로** 보겠다는 뜻입니다.
- `LSTM(10, return_sequences=True)`로 하면 `(None, 529, 10)`이 되어 뒤에 또 LSTM을 붙일 수 있습니다. `return_sequences=False`(기본값)면 마지막 시간만 남겨 `(None, 10)`이 됩니다. 코드 주석에도 이 차이가 적혀 있습니다.
- `LSTM(10)`의 파라미터 수는 `4 × 10 × (16 + 10 + 1) = 1,080개`였습니다(실제 `count_params()` 확인).

## 5. 표 데이터를 GRU에 넣기 — 8개 특징을 8개 "시간"으로 (`keras2/keras64_LSTM01_calfifornia.py`)

캘리포니아 집값 데이터는 표입니다. 행이 집, 열이 특징 8개입니다.

```python
x_train.shape -> (15480, 8)      # 20640개 중 75%
x_train = x_train.reshape(-1, 8, 1)   # (15480, 8, 1)
model.add(GRU(units=10, input_shape=(8, 1)))
```

- `reshape(-1, 8, 1)`은 "특징 8개를 **8개의 시간**으로, 각 시간의 값은 1개"라고 알려 주는 것입니다. 표 데이터에는 원래 시간 순서가 없는데 억지로 시간처럼 본 것이라, 특징 순서를 바꾸면 결과도 달라질 수 있습니다.
- `scaler.fit_transform(x_train)`은 학습 데이터로 기준을 만들고, `scaler.transform(x_test)`는 **같은 기준**으로 테스트를 바꿉니다. 테스트로 새 기준을 만들면 안 됩니다(`fit_transform`을 쓰면 안 되는 자리).
- `GRU(10)`의 파라미터는 `3 × 10 × (1 + 10 + 2) = 390개`였습니다. GRU는 문 3개(업데이트·리셋·후보), LSTM은 문 4개라 같은 10유닛이면 `4 × 10 × (1 + 10 + 1) = 480개`로 더 많습니다.

### 회귀 문제에서 `metrics=['acc']`는 의미가 없습니다

이 파일은 `loss='mse'`(집값 숫자 맞추기)인데 `metrics=['acc']`를 씁니다. 집값은 `0.15 ~ 5.00` 사이의 **연속된 숫자**라서 "정답 클래스를 몇 개 맞혔나"를 셀 수 없습니다.

- 실제로 4000개로 3에폭 학습해 보니 `loss`는 `3.8278 → 1.337 → 1.3296`으로 줄었는데 `acc`는 `0.0006 → 0.0028`에 머물렀습니다.
- 파일 주석의 마지막 줄 `[0.2755866050720215, 0.0027131782844662666]`도 같은 구조입니다. 앞 숫자는 `mse`(의미 있음), 뒤 숫자 `0.0027`은 `acc`(거의 항상 0, 의미 없음)입니다.
- `model.evaluate`는 컴파일할 때 적은 지표를 **적은 순서대로** 돌려줍니다. 그래서 `loss[0]`이 손실, `loss[1]`이 그 지표입니다. 회귀에서는 `metrics=['mae']`를 쓰거나 `evaluate`의 첫 값만 보면 됩니다.

## 6. 784 타임스텝 LSTM이 실패한 이유 (`keras2/keras64_LSTM11_minist.py`)

이 파일은 28×28 그림을 `reshape(-1, 784, 1)`로 펴서 LSTM에 넣습니다. 주석의 결과는 `loss 2.3011 / acc 0.1135`인데, 이 숫자는 **거의 찍기에 가깝습니다**.

- 10개 클래스를 아무렇게나 고르면 정답률은 약 `1/10 = 0.10`입니다. 또 확률을 0.1씩 고르게 내면 손실이 `-ln(0.1) = 2.3026`이 됩니다. `2.3011`은 이 값과 거의 같습니다.
- 실제로 2000개만 1에폭 학습해 확인해 보니 `acc 0.1037`, `val_acc 0.0975`였고, 500개를 예측하자 **500개 전부 7번 클래스**로 답했습니다(정답은 39~66개씩 골고루). 즉 모델이 "하나만 찍는" 상태에 빠졌습니다.
- 이유: 28×28 그림을 784칸 일렬로 펴면 **위아래 이웃 픽셀이라는 정보가 사라집니다**. 게다가 LSTM이 784번의 시간을 거슬러 기억을 들고 가야 해서 학습이 매우 어려워집니다. 그림에는 `Conv2D`(이웃을 함께 보는 층)가 맞습니다.
- 이 파일 아래쪽 주석 `509.7초 / 0.3589 / 0.9016`은 **복사해 온 앞 파일(`keras63_sparse1_minist.py`)의 결과**입니다. 이 파일 자신의 결과는 그 아래 `839.11초 / 2.3011 / 0.1135`입니다.

## 쉬운 예시로 정리

- **Conv2D**: 방석 28칸 위에 손바닥(3칸)을 올려 놓고 한 칸씩 옮기며 누르는 놀이. 손바닥이 방석 밖으로 나갈 수 없으니 누를 수 있는 시작점은 `28-3+1=26`개입니다.
- **argmax**: 10명의 심사위원이 점수를 줬을 때(`(10,)`), 가장 높은 점수를 준 심사위원의 **번호**를 고르는 일. `axis=1`은 "그림마다 심사위원 중 1등", `axis=0`은 "심사위원마다 가장 점수 높은 그림".
- **Reshape**: 같은 12개의 블록을 `3×4`로도, `2×6`으로도 쌓을 수 있습니다. 블록 개수가 다르면 쌓을 수 없어서 오류가 납니다.
- **784 타임스텝 LSTM**: 784쪽짜리 책을 한 권 통째로 읽고 마지막에 한 문장으로 요약하라는 것과 같습니다. 그림은 28줄짜리 짧은 편지 28통을 나눠 읽는 `Conv2D`가 훨씬 쉽습니다.

## 반드시 기억할 점

- `Conv2D` 출력 크기(패딩 없음) = `입력 - 필터 + 1`. 채널 수는 **필터 개수**입니다.
- `Dropout`·`GlobalAveragePooling2D`는 모양을 줄이지만 채널 수는 유지/집계합니다. `GlobalAveragePooling2D` 뒤에는 `(채널,)` 1차원이 됩니다.
- 정답이 정수 하나면 `sparse_categorical_crossentropy`, 원-핫이면 `categorical_crossentropy`입니다. 정수 라벨에 categorical을 쓰면 `Shapes (None, 1) and (None, 10) are incompatible`가 납니다.
- `predict` 결과는 `(샘플, 클래스)` 점수표입니다. 클래스 하나를 고르려면 `np.argmax(..., axis=1)`.
- `Reshape`는 **원소 개수가 같아야** 합니다. `28×280 = 28×28×10 = 7,840`.
- 표 데이터를 LSTM/GRU에 넣을 때 `(샘플, 특징 수, 1)`로 바꾸면 "특징 = 시간"으로 보는 것입니다.
- 회귀(`mse`)에 `metrics=['acc']`를 붙이면 그 숫자는 거의 항상 0이라 아무 의미가 없습니다.
- 10클래스 랜덤 손실은 `ln(10) ≈ 2.30`입니다. 손실이 2.30 근처면 "아직 아무것도 배우지 못한 상태"로 보면 됩니다.

## 주석·기록과 실제가 다른 곳

1. `keras63_sparse1_minist.py` 44행 `# (22, 22, 6)` → 실제는 `(22, 22, 16)`(필터 16개)
2. `keras63_sparse1_minist.py` 100·103행 `# (10,) (10000,)` → 실제는 `(10000,) (10000,)` (`predict` 후 `argmax(axis=1)`이므로)
3. `keras64_LSTM11_minist.py` 95~98행 결과 주석은 앞 파일 복사본 → 이 파일 결과는 102~105행(`2.3011 / 0.1135`)
4. `keras64_LSTM01_calfifornia.py` `metrics=['acc']` → 회귀라서 의미 없음(실측 `0.0027`)
5. `keras63_sparse1_minist.py`는 `Flatten`을 import만 하고 사용하지 않음(실제로는 `GlobalAveragePooling2D` 사용)
6. `keras63_sparse3_cifar10.py` 82행 `y_test = np.argmax(y_test, axis=1)`이 주석 처리된 상태에서 `accuracy_score(y_test, y_predict)`를 호출합니다. `y_test`가 `(N,1)`, `y_predict`가 `(N,)`인데도 sklearn이 1차원으로 펴서 계산하므로 값은 맞게 나옵니다(4개 예시로 확인: `0.75`). 다만 `np.mean(y_test == y_predict)`처럼 직접 비교하면 `(N,N)`으로 퍼져 엉뚱한 값이 나옵니다(10000개 예시: `0.10` vs 올바른 `0.0989`).
