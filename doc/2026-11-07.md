## 1. GridSearchCV와 RandomizedSearchCV

모델에는 조절할 수 있는 설정값(하이퍼파라미터)이 있습니다. 예를 들면 트리의 깊이 `max_depth`, 학습률 `learning_rate`, 나무 수 `n_estimators`입니다.

- `GridSearchCV`는 적어 둔 조합을 **모두** 시험합니다.
- `RandomizedSearchCV`는 가능한 조합 중 일부를 무작위로 뽑아 시험합니다. `n_iter=3`이면 3개 후보를, 생략하면 기본 `n_iter=10` 후보를 뽑습니다.
- `cv=5`는 각 후보를 5개의 교차검증 나눔으로 평가한다는 뜻입니다. 예를 들어 후보 42개라면 교차검증 학습은 `42 × 5 = 210`회입니다. 기본 `refit=True`이면 검색 후 가장 좋은 후보를 전체 학습 자료에 한 번 더 맞춥니다.

`parameters`가 여러 사전의 목록이면 사전끼리 모든 키를 섞지 않습니다. 각 사전 안에서 조합을 만들고, 사전별 조합 수를 더합니다.

| 코드에서 읽은 설정 | 파라미터 공간 조합 수 | 실제 평가 후보 수 | 5-fold 교차검증 학습 횟수 |
|---|---:|---:|---:|
| Iris GridSearch | 42 | 42 | 210 |
| Digits GridSearch (`ml08_GridSearchCV_01_digits.py`, `ml09_RandomSearchCV_01_digits.py`) | 105 | 105 | 525 |
| Diabetes GridSearch | 234 | 234 | 1,170 |
| Iris RandomizedSearch (`n_iter=3`) | 42 | 3 | 15 |
| Diabetes RandomizedSearch (기본 `n_iter=10`) | 234 | 10 | 50 |

이는 소스의 설정으로 계산한 **예정 횟수**이지, 이번 환경에서 실제 모델 학습을 끝냈다는 뜻은 아닙니다. Digits·Diabetes GridSearch 세 코드의 주석에는 후보 수를 42라고 적었지만 실제 grid는 각각 105개와 234개입니다. 특히 `ml09_RandomSearchCV_01_digits.py`는 파일명과 달리 `RandomizedSearchCV`가 아니라 `GridSearchCV`를 생성합니다. Diabetes RandomizedSearch는 234개 조합 공간 중 기본 `n_iter=10`개를 선택합니다.

## 2. 분류와 회귀는 서로 다른 문제

- **분류**는 정답이 종류(예: 숫자 0~9, 꽃 종류)입니다. `XGBClassifier` 같은 분류기를 쓰고, 보통 정확도(accuracy)를 봅니다. `StratifiedKFold`는 각 fold에 분류 라벨 비율을 비슷하게 나누는 데 적합합니다.
- **회귀**는 정답이 연속된 숫자(예: 당뇨병 지표, 집값)입니다. `XGBRFRegressor` 같은 회귀기를 쓰고, R²·MAE·RMSE 같은 회귀 지표를 봅니다. 연속형 정답에는 보통 `KFold`를 사용합니다.

소스에서 바로잡아야 할 조합:

- `load_digits`는 숫자 분류 데이터인데 `XGBRFRegressor`를 사용한 파일이 있습니다. 회귀기의 기본 `score`는 R²이므로 분류 정확도를 측정하지 않습니다. 의도가 숫자 분류라면 분류기와 분류 지표를 사용해야 합니다. `ml09_RandomSearchCV_01_digits.py`도 파일명과 달리 `GridSearchCV`를 사용합니다.
- `load_diabetes`의 `y`는 연속형 회귀 정답인데 `XGBRFRegressor`에 `StratifiedKFold`를 함께 쓴 파일들이 있습니다. Stratified는 분류 라벨을 나누는 용도이므로 회귀에서는 `KFold` 등으로 바꾸어야 합니다.
- `ml06_all_estimators1_데이터까지.py`는 `load_diabetes`를 분류 데이터 목록에 넣고 `stratify=y`를 사용합니다. 이름표에는 `디지트`라고 적혀 있지만 실제 데이터는 Diabetes입니다.
- `ml06_all_estimators2_데이터까지.py`는 회귀 모델을 모으면서 `accuracy_score`를 사용합니다. 연속형 예측값에 정확도를 적용하는 것은 맞지 않습니다. 예외를 모두 숨기는 `except: continue` 때문에 모델 실패 원인도 보이지 않으며, 유효 모델이 없으면 마지막 `np.argmax`에서 실패할 수 있습니다.
- `ml07_for로파라미터튜닝.py`도 연속형 Diabetes 정답에 `HistGradientBoostingClassifier`를 사용합니다. 회귀 문제라면 회귀 추정기와 회귀 평가 지표로 바꾸어야 합니다.

## 3. 교차검증과 시험 데이터 누수

올바른 기본 흐름은 다음과 같습니다.

```text
전체 자료 → train / test 분리
train 안에서 교차검증으로 모델·설정 선택
선택이 끝난 모델을 test에서 마지막으로 한 번 평가
```

시험 자료(`x_test`, `y_test`)는 모델을 고르는 동안 사용하지 않습니다. `ml06` 파일은 `cross_val_predict`를 `x_test`, `y_test`에 적용해 그 점수로 모델을 고르므로, 시험 자료가 선택 과정에 들어갑니다. `ml07`도 여러 설정의 점수를 같은 test에서 비교해 최적 설정을 고릅니다. 이러면 마지막 평가에 쓸 독립된 시험 자료가 남지 않습니다.

또한 `StandardScaler.fit_transform(x_train)`을 먼저 한 뒤 그 자료로 교차검증하면, 각 fold의 검증 부분 통계가 scaler에 섞일 수 있습니다. 전처리와 모델을 `Pipeline`으로 묶으면 각 fold의 학습 부분에서만 scaler가 맞춰집니다.

```python
pipe = make_pipeline(StandardScaler(), estimator)
scores = cross_val_score(pipe, x_train, y_train, cv=KFold(n_splits=5, shuffle=True, random_state=33))
```

`best_score_`는 SearchCV가 train 안의 교차검증에서 얻은 최선의 평균 점수입니다. `score(x_test, y_test)`는 따로 보관한 test 자료에 대한 평가입니다. 두 값을 같은 것으로 보거나 test로 최적 파라미터를 고르면 안 됩니다.

## 4. Keras Diabetes 하이퍼파라미터 코드

`keras2/keras77_hyperParameter_02_diabetes.py`의 자료는 `load_diabetes()`에서 가져옵니다. 코드 주석의 shape는 `x=(442, 10)`, `y=(442,)`입니다. 입력 특성 10개를 받아 마지막 `Dense(1, activation='linear')`에서 연속된 값 하나를 내므로 회귀 문제에 맞는 출력 모양입니다.

- `build_model()`은 입력 10개짜리 함수형 Keras 모델을 만들고, Dense 층과 Dropout 층을 이어 붙인 뒤 `mse` 손실로 compile합니다.
- `KerasRegressor`는 Keras 모델을 scikit-learn 검색 도구가 다룰 수 있게 감싸는 wrapper입니다.
- `RandomizedSearchCV`는 후보 10개, `cv=3`이므로 교차검증 fit은 30회이고, 기본 `refit=True`에 따라 최종 재학습도 한 번 더 합니다. `epochs=1000`은 각 fit의 최대 epoch 수이며 EarlyStopping이 조건에 따라 먼저 멈출 수 있습니다.
- `lr` 인자는 검색 후보 사전에 없고 `build_model()`의 optimizer 설정에도 연결되지 않습니다. `compile()`에는 `optimizer` 이름 문자열만 전달되므로 learning rate를 탐색하지 않습니다. `ModelCheckpoint`도 가져오기만 하고 사용하지 않으며, 빈 `parameter`도 실제 검색에 쓰이지 않습니다. 이런 부분은 설정값이 실제 모델에 반영되는지 확인해야 합니다.
- 파일 안의 `loss` 주석 숫자와 실행 시간은 과거 기록일 수 있습니다. 현재 환경에서 다시 실행한 결과로 확인하지 않았습니다.

**NumPy:** `np.argmax(model_acc)`는 가장 큰 점수의 **위치 번호(index)** 를 돌려줍니다. 예를 들어 점수 배열 `[0.55, 0.81, 0.74]`이면 위치 1을 반환하므로, 같은 위치의 모델 이름을 찾아야 합니다. 점수가 비어 있으면 선택할 최대값 자체가 없어 오류가 날 수 있습니다.

기초 shape 확인 예시로 `np.array([range(6), range(10, 16)])`는 `(2, 6)`이고, `.T`를 붙이면 `(6, 2)`가 됩니다. 전치는 기존 축의 순서를 바꾸며 새 차원을 추가하지 않습니다. 여러 입력 배열과 정답을 나눌 때도 한 번의 `train_test_split(x1, x2, y, ...)` 호출로 나누어 같은 샘플 인덱스를 유지해야 합니다. 행 수가 같아도 순서를 따로 섞으면 입력과 정답이 잘못 짝지어져 오류 없이 학습이 망가질 수 있습니다.

**pandas:** day45/day46의 추가 Python 파일에서는 pandas를 사용하지 않았습니다. 기초 복습 예로 `df.drop(['target'], axis=1)`에서 `axis=1`은 열 방향이므로 `target` 열을 제거하고, `axis=0`은 행 방향을 뜻합니다.
