## 중요한 내용

### 1. 대화 기록을 RAG에 넣는 흐름

`reg21_Gradio_history.py`는 저장된 FAISS 벡터 DB를 불러오고, 질문과 가까운 문서를 retriever로 찾은 뒤, 문서 내용과 이전 대화를 함께 모델에 전달합니다.

흐름은 다음과 같습니다.

1. `HuggingFaceEmbeddings`로 질문과 문서를 같은 방식의 숫자 벡터로 표현한다.
2. `FAISS.load_local()`로 기존 인덱스를 읽는다.
3. `as_retriever(search_kwargs={"k": 2})`가 가까운 문서 조각 2개를 고른다.
4. `ChatPromptTemplate.from_messages()`에서 system 메시지, `{context}`, `MessagesPlaceholder(variable_name='chat_history')`, 현재 `{input}`을 조합한다.
5. Gradio가 넘긴 `history`의 user/assistant 항목을 `HumanMessage`와 `AIMessage`로 바꾼다.
6. `rag_chain.invoke()`가 검색 결과와 대화 기록을 이용해 `response['answer']`를 반환한다.

`MessagesPlaceholder`는 대화 기록이 들어갈 자리를 미리 마련하는 부품입니다. 기록을 넣는다고 해서 모델이 모든 사실을 자동으로 기억하는 것은 아니며, prompt에 실제 메시지 목록을 전달해야 합니다.

`allow_dangerous_deserialization=True`는 저장 파일을 역직렬화하도록 허용할 뿐입니다. 신뢰할 수 있는 FAISS 파일에만 사용해야 하며, 안전 검사가 되는 옵션은 아닙니다.

### 2. 다중 출력 모델

`keras69_ensemble4.py`는 입력 하나를 여러 Dense 층에 통과시킨 뒤 `last_output1`, `last_output2` 두 개를 출력합니다. 따라서 `model = Model(..., outputs=[last_output1, last_output2])`이고, `fit()`과 `evaluate()`의 정답도 `[y1, y2]` 같은 순서의 목록이어야 합니다.

코드에서 `last_dense1`, `last_dense2`를 만들었지만 `last_output1`은 `merge3`에 바로 연결되어 있습니다. 따라서 `ld1`, `ld2`는 계산 그래프의 최종 출력에 사용되지 않습니다. 층을 정의했다는 사실과 실제 출력 경로에 연결했다는 사실은 다릅니다.

또한 `merge2`도 만들어졌지만 이후 사용되지 않고, 두 출력 모두 `merge3`에서 바로 만들어집니다. 이것은 Python 문법 오류는 아니지만, 작성자가 의도한 모델 구조와 실제 모델 구조가 다를 수 있는 지점입니다.

### 3. 세 주가 데이터를 맞춰 시계열 모델에 넣기

`keras70_1_주가맞추기.py`는 아모레퍼시픽, 하이닉스, 삼성전자 CSV를 읽고 날짜를 기준으로 맞춥니다. `x1`과 `x2`는 삼성전자 날짜 목록에 있는 행만 남기고, `reset_index(drop=True)`로 새 행 번호를 붙입니다. 이후 날짜 열은 제거하고 숫자 feature만 모델 입력으로 사용합니다.

`split_xy(dataset, size=20)`은 연속된 20일을 하나의 샘플로 만듭니다. 원래 데이터가 1120일이면 window 수는 `1120 - 20 + 1 = 1101`개입니다. 각 입력은 `(샘플 수, 20, feature 수)` 모양이 되고, 주가 예측 대상 `y_windowed`는 각 20일 window의 마지막 날짜에 맞춰 `y_data[19:]`로 자릅니다.

학습·테스트는 앞의 80%를 학습, 뒤의 20%를 테스트로 나눕니다. 시계열에서는 미래 정보가 과거 학습에 섞이지 않도록 시간 순서를 지키는 것이 중요합니다.

각 X scaler는 학습 데이터만으로 `fit()`하고 테스트에는 `transform()`만 합니다. y도 `y_train`으로만 `fit()`한 뒤 `y_test`를 변환합니다. 이렇게 해야 테스트 데이터의 정보를 미리 보고 학습하는 데이터 누수(leakage)를 줄일 수 있습니다.

### 4. 여러 신경망 가지를 합치기

아모레퍼시픽과 하이닉스 입력은 각각 LSTM 여러 층을 통과하고, 삼성전자 입력은 Conv1D와 Flatten을 통과합니다. 세 가지 결과를 `Concatenate()`로 합친 다음 Dense 층과 최종 1개 출력으로 보냅니다.

- `input_amore`: `(batch, 20, 6)`
- `input_hynix`: `(batch, 20, 6)`
- `input_samsung`: `(batch, 20, 5)`
- 최종 출력: `(batch, 1)`

LSTM의 `return_sequences=True`는 각 timestep의 출력을 다음 LSTM에 계속 전달할 때 사용합니다. 마지막 LSTM은 기본값이 `False`이므로 마지막 시점의 요약 벡터를 다음 Dense 층으로 보냅니다. Conv1D는 시간축 주변의 짧은 패턴을 찾고, `Flatten`은 그 결과를 Dense 층이 받을 수 있는 2차원 형태로 펼칩니다.

## 반드시 기억할 점

- `MessagesPlaceholder`는 대화 기록의 자리이며, 실제 `HumanMessage`·`AIMessage` 목록을 넣어야 한다.
- RAG의 retriever는 문서를 찾고, LLM은 그 문서와 질문을 바탕으로 답을 만든다.
- 다중 출력 모델의 출력 순서와 정답 목록 순서는 일치해야 한다.
- 계산 그래프에 연결되지 않은 층은 모델 출력에 영향을 주지 않는다.
- 시계열 데이터는 시간 순서를 보존해 분할한다.
- scaler는 train 데이터로만 `fit()`하고 test에는 `transform()`한다.
- `(샘플, timestep, feature)`에서 20은 각 샘플이 보는 연속 날짜 수이다.
- 코드 주석의 loss와 예측값은 기록일 뿐이며, 이번 실행에서 재현한 결과라고 단정할 수 없다.
- 주가 예측은 학습 모델의 실험 코드이며 실제 투자 판단이나 미래 가격을 보장하지 않는다.

## 코드 흐름과 shape 설명

1. pandas로 세 CSV를 읽고 날짜 오름차순으로 정렬한다.
2. 삼성전자 날짜와 겹치는 행만 남겨 세 입력의 시간축을 맞춘다.
3. 날짜 열을 제거하고 20일 window를 만든다.
4. 앞 80%와 뒤 20%를 시간 순서대로 분리한다.
5. X는 feature별 scaler로, y는 별도 scaler로 변환한다.
6. 두 LSTM 가지와 한 Conv1D 가지를 구성해 `Concatenate`한다.
7. `validation_split=0.2`로 학습 내부의 validation을 만들고 callback으로 `val_loss`를 관찰한다.
8. 마지막 20일을 `(1, 20, feature 수)`로 바꿔 예측한 뒤 `inverse_transform()`으로 가격 단위로 되돌린다.

## 쉬운 예시

세 친구가 같은 날짜의 일기를 각각 썼다고 해 봅시다. 한 친구의 1월 1일 기록과 다른 친구의 1월 10일 기록을 묶으면 하루의 상황을 제대로 비교할 수 없습니다. 그래서 먼저 날짜가 같은 줄끼리 맞춘 뒤, 20일씩 묶어 모델에 보여줍니다.

대화 기록은 책갈피와 비슷합니다. 사용자가 “그럼 두 번째 방법은?”이라고 물었을 때, 이전 질문과 답변이 함께 있어야 “두 번째 방법”이 무엇인지 알 수 있습니다. `MessagesPlaceholder`는 그 책갈피를 꽂을 자리입니다.
