## 1. 이미지에 `Conv1D`를 넣는다는 것

`Conv1D`는 원래 "시간 순서가 있는 값"을 보는 층입니다. 입력은 항상 3차원 `(샘플 수, 시점 수, 시점마다의 특징 수)`입니다.

이미지는 `(샘플, 세로, 가로)` 또는 `(샘플, 세로, 가로, 색)` 4차원입니다. 그래서 이미지를 `Conv1D`에 넣으려면 **세로·가로·색 중 무엇을 "시점"으로 삼을지** 사람이 정해서 3차원으로 접어야 합니다.

| 파일 | 원래 데이터 | `Conv1D`에 넣은 모양 | 시점이 뜻하는 것 | 시점마다의 특징 |
|---|---|---|---|---|
| `10_digits` | `(1797, 64)` (8×8 그림을 편 것) | `(1257, 64, 1)` | 픽셀 1개 | 값 1개(회색 농도) |
| `12_fashion` | `(60000, 28, 28)` | `(60000, 28, 28)` | **세로 1줄(행)** | 그 줄의 가로 28칸 |
| `14_cifar100` | `(50000, 32, 32, 3)` | `(50000, 1024, 3)` | 픽셀 1개 | 색 3개(R,G,B) |

- `12_fashion`은 세로 방향으로 줄을 훑습니다. 커널 `(2,)`는 "위 줄과 아래 줄"을 한 번에 봅니다.
- `10_digits`와 `14_cifar100`은 픽셀을 일렬로 세웁니다. 커널 `(2,)`는 "바로 다음 픽셀"을 봅니다.

## 2. `keras68_Conv1D_10_digits.py` — 8×8 그림을 64칸으로 펴기

```python
x = datasets.data          # (1797, 64)
x_train = x_train.reshape(-1, 64, 1)   # (1257, 64, 1)

model.add(Conv1D(20, (4,), input_shape=(64, 1)))
model.add(Conv1D(40, (2,)))
model.add(GlobalAveragePooling1D())
model.add(Dense(64, activation='relu'))
model.add(Dense(32, activation='relu'))
model.add(Dense(10, activation='softmax'))
```

- `datasets.data`는 이미 `8×8` 그림을 **72 → 8** 식으로 한 줄로 편 배열입니다. 실제로 확인했습니다: `datasets.images[0].reshape(-1)`과 `datasets.data[0]`이 완전히 같고, `data[0][8]`은 `images[0][1,0]`(둘째 줄 첫 칸)과 같습니다. 즉 **8칸마다 줄이 바뀝니다.**
- 그래서 커널 `(4,)`는 대부분 "한 줄 안의 이웃 4칸"을 보지만, 8칸마다 경계에서는 **줄 끝과 다음 줄 시작**을 이웃으로 봅니다. 8의 배수 자리에서만 생기는 작은 어긋남입니다.

실제 층별 모양과 파라미터(실행 확인):

| 층 | 출력 모양 | 파라미터 계산 | 파라미터 |
|---|---|---|---|
| `Conv1D(20, (4,))` | `(None, 61, 20)` | `(4×1+1)×20` | 100 |
| `Conv1D(40, (2,))` | `(None, 60, 40)` | `(2×20+1)×40` | 1,640 |
| `GlobalAveragePooling1D()` | `(None, 40)` | 없음 | 0 |
| `Dense(64, relu)` | `(None, 64)` | `40×64+64` | 2,624 |
| `Dense(32, relu)` | `(None, 32)` | `64×32+32` | 2,080 |
| `Dense(10, softmax)` | `(None, 10)` | `32×10+10` | 330 |
| **합계** | | | **6,774** |

- 시점 길이는 `64 → 61 → 60`으로 줄어듭니다(`길이-커널+1`).
- `Conv1D` 파라미터는 **시점 개수와 무관**합니다. `(커널×입력채널+1)×필터` 하나만 기억하면 됩니다.

### `GAP`가 위치 정보를 지운다 — 같은 데이터로 비교

`GlobalAveragePooling1D`는 시점 방향으로 **평균**을 냅니다. 숫자(정확히는 그림의 모양)를 맞히는 문제에서는 "어느 위치에 획이 있는가"가 중요한데, 평균을 내면 그 정보가 사라집니다.

같은 데이터·같은 분할(`random_state=421`, `train_size=0.7`)·같은 스케일(`RobustScaler`)로 40에폭씩 돌려 확인했습니다.

| 마지막 부분 | 테스트 정확도 | 총 파라미터 |
|---|---|---|
| `GAP → Dense(64) → Dense(32) → Dense(10)` | **0.4333** | 6,774 |
| `Flatten → Dense(64) → Dense(32) → Dense(10)` | **0.9389** | 157,814 |

- `Flatten`은 60×40=2,400개를 그대로 펴서 어느 시점의 어떤 특징이었는지를 살립니다. 그래서 파라미터가 15만 개로 늘지만 정확도가 0.94까지 올라갑니다.
- `GAP`는 40개로 줄여서 6,774개만 남습니다. 파일 아래 주석에 찍힌 `acc : 0.4907`도 이 구조에서 나온 값으로 보입니다(주석 값 자체는 재현하지 않았습니다).
- 5에폭만 돌리면 `GAP` 모델은 정확도 0.2481이었습니다. 학습이 느릴 뿐 아니라 **구조 자체가 불리**하다는 것을 알 수 있습니다.
- 정리: 이미지처럼 "위치가 중요한" 데이터에서는 `GAP`보다 `Flatten`(또는 `GAP`를 쓰더라도 층을 더 쌓아 특징을 살리는 구조)이 잘 맞습니다.

### 작은 주의점

- `EarlyStopping(patience=800)`에 `epochs=100`입니다. `patience`가 `epochs`보다 크므로 **조기 종료가 걸릴 수 없습니다.** (40에폭 실행에서도 한 번도 걸리지 않았습니다.)

## 3. `keras68_Conv1D_12_fashion.py` — `(28, 28)`은 "줄 28개 × 칸 28개"

```python
(x_train, y_train), (x_test, y_test) = fashion_mnist.load_data()  # (60000, 28, 28)
x_train = (x_train - 127.5) / 127.5      # 0~255 -> -1~1
x_train = x_train.reshape(-1, 28, 28)    # 모양은 그대로(이미 3차원)

model.add(Conv1D(32, (2,), input_shape=(28, 28)))
```

- `input_shape=(28, 28)`은 "시점 28개, 시점마다 특징 28개"입니다. 옷 사진에서는 **세로 1줄이 시점 1개**, 그 줄의 **가로 28칸이 특징 28개**가 됩니다.
- 커널 `(2,)`는 "위 줄 + 아래 줄"을 함께 봅니다. 즉 2×28 = 56픽셀짜리 얇은 띠를 보는 셈입니다.
- `(x - 127.5) / 127.5`는 0을 0으로, 0과 255를 각각 -1과 1로 옮기는 계산입니다. 실제로 `[0, 255, 127.5]`를 넣으면 `[-1, 1, 0]`이 나옵니다.

실제 층별 모양과 파라미터(실행 확인):

| 층 | 출력 모양 | 파라미터 |
|---|---|---|
| `Conv1D(32, (2,))` | `(None, 27, 32)` | `(2×28+1)×32 = 1,824` |
| `Dropout(0.2)` | `(None, 27, 32)` | 0 |
| `Conv1D(64, (3,), relu)` | `(None, 25, 64)` | `(3×32+1)×64 = 6,208` |
| `Dropout(0.1)` | `(None, 25, 64)` | 0 |
| `Conv1D(72, (2,), relu)` | `(None, 24, 72)` | `(2×64+1)×72 = 9,288` |
| `Dropout(0.3)` | `(None, 24, 72)` | 0 |
| `Conv1D(41, (3,), relu)` | `(None, 22, 41)` | `(3×72+1)×41 = 8,897` |
| `Flatten()` | `(None, 902)` | 0 (`22×41`) |
| `Dense(44, relu)` | `(None, 44)` | `902×44+44 = 39,732` |
| `Dropout(0.2)` | `(None, 44)` | 0 |
| `Dense(10, softmax)` | `(None, 10)` | `44×10+10 = 450` |
| **합계** | | **66,399** |

- 시점 길이는 `28 → 27 → 25 → 24 → 22`로 줄어듭니다.
- 이 모델은 `GAP`가 아니라 `Flatten`을 씁니다. 그래서 `Dense` 한 층(39,732개)이 전체 파라미터의 60%를 차지합니다.
- 작은 재현(훈련 10,000장, 3에폭, 같은 설정)에서 테스트 정확도 **0.8032**가 나왔습니다(6.9초). 이미지에 `Conv1D`를 써도 어느 정도는 학습이 됩니다. 다만 파일 주석의 `0.9184`는 60,000장·수백 에폭 설정의 기록이며 이번에 재현하지 않았습니다.

### `Dropout`은 3차원에서 무엇을 끄는가

`Conv1D` 뒤에 `Dropout`을 쓰면 "시점 하나를 통째로 끈다"고 오해하기 쉽습니다. 실제로 확인해 보니 **값 하나하나를 따로 끕니다.** `(2, 4, 3)` 모양의 모두-1 배열에 `Dropout(0.5)`를 적용하면

```text
[[[0. 2. 2.]
  [0. 0. 2.]
  [2. 0. 2.]
  [2. 2. 2.]]
 ...
```

처럼 칸별로 0이 되고, 살아남은 값은 `1/(1-0.5) = 2`배로 커집니다. 즉 시점 단위가 아니라 원소 단위로 꺼집니다.

### `OneHotEncoder`를 테스트에 또 `fit`하는 실수

```python
y_train = ohe.fit_transform(y_train.reshape(-1, 1))
y_test  = ohe.fit_transform(y_test.reshape(-1, 1))   # ← fit을 또 한다
```

- `fit`은 "이 데이터에 어떤 종류(클래스)가 있는지"를 **새로 조사해** 열 순서를 정합니다. 테스트에 `fit`을 하면 훈련에서 정한 기준을 버리고 테스트 기준으로 다시 정하는 셈입니다.
- 패션 MNIST는 훈련·테스트 모두 0~9가 다 있어서 이번에는 우연히 열이 10개로 같습니다. 하지만 테스트에 한 클래스가 빠지면 열이 9개가 됩니다. 실제로 확인했습니다: 훈련에 10종류, 테스트에 9종류를 넣으면 `train (100, 10)` / `test (9, 9)`가 되고, 이 라벨로 10개 출력 모델을 평가하면 `ValueError`가 납니다.
- 올바른 방법은 `ohe.fit(y_train)` → `ohe.transform(y_train)` / `ohe.transform(y_test)`입니다. 테스트에 없는 클래스는 0으로 채워진 열이 됩니다. 또는 케라스의 `to_categorical`을 쓰면 열 개수를 직접 정할 수 있습니다.

### 주석·import에서 실제와 다른 곳

- `# x 데이터 4차원 데이터로 변경`이라고 적혀 있지만, 실제 코드는 `reshape(-1, 28, 28)`로 **3차원**을 만듭니다(4차원은 `Conv2D`용).
- `# MaxAbsScaler 데이터 스케일링`이라고 적혀 있지만, 실제 계산은 `(x-127.5)/127.5`입니다. 이는 최솟값을 -1, 최댓값을 1로 옮기는 **min-max 방식**이고, `MaxAbsScaler`(최댓값의 절댓값으로 나누기)와는 다릅니다.
- `MaxPooling2D`를 import했지만 한 번도 쓰지 않습니다(`Conv1D` 모델이라 `MaxPooling1D`여야 맞습니다).
- `print(x_train.shape, x_test.shape)`가 그대로 남아 있습니다.

## 4. `keras68_Conv1D_14_cifar100.py` — `(1024, 3)`으로 펴면 생기는 경계 문제

```python
(x_train, y_train), _ = cifar100.load_data()   # (50000, 32, 32, 3)
x_train = x_train.reshape(-1, 1024, 3)         # 32×32 = 1024 픽셀, 색 3개

model.add(Conv1D(16, (2,), input_shape=(1024, 3)))
model.add(GlobalAveragePooling1D())
model.add(Dense(41, activation='relu'))
model.add(Dense(100, activation='softmax'))
```

- `3072 = 1024 × 3`이므로 접는 것 자체는 됩니다. 하지만 **시점 1024개가 "한 줄로 편 픽셀"** 이라는 점이 중요합니다.
- NumPy `reshape`는 **행 우선(앞에서부터 차례대로)** 으로 채웁니다. 그래서 시점 0~31은 첫째 줄, 시점 32~63은 둘째 줄입니다. 실제로 확인했습니다: 32×32 그림에서 `시점 31 == [0, 31]`, `시점 32 == [1, 0]`.
- 커널 `(2,)`는 시점 31과 32를 **이웃**으로 봅니다. 그림에서는 오른쪽 끝과 다음 줄 왼쪽 끝, 즉 **서로 멀리 떨어진 두 점**입니다. 1024개 중 31개 경계에서 이런 일이 생깁니다.

실제 모델(실행 확인, 합성 데이터로 구조 검증):

| 층 | 출력 모양 | 파라미터 |
|---|---|---|
| `Conv1D(16, (2,))` | `(None, 1023, 16)` | `(2×3+1)×16 = 112` |
| `GlobalAveragePooling1D()` | `(None, 16)` | 0 |
| `Dense(41, relu)` | `(None, 41)` | `16×41+41 = 697` |
| `Dense(100, softmax)` | `(None, 100)` | `41×100+100 = 4,200` |
| **합계** | | **5,009** |

- 100종류를 맞히는 모델의 파라미터가 **5,009개**뿐입니다. 참고로 같은 문제를 `Conv2D(16, (2,2))`로 시작하면 `(32,32,3)` 입력에서 파라미터가 `(2×2×3+1)×16 = 208`개이고, 공간 구조(가로·세로 이웃)를 제대로 봅니다.
- 첫 `Conv1D`에 `activation`이 없어 선형입니다(10-29에서 배운 것과 같은 이유로, 층을 쌓아도 표현력이 늘지 않습니다).
- 파일 주석의 `acc 0.3792`는 원본 실행 기록이며 이번에 재현하지 않았습니다. cifar-100 전체 데이터(169MB) 내려받기가 이 환경에서 매우 느려 중단했고, 모델 구조·모양·파라미터·`reshape` 순서만 합성 데이터로 확인했습니다.
- 고치는 방법: `x.reshape(-1, 32, 32, 3)`으로 **4차원을 유지**하고 `Conv2D`를 씁니다. 굳이 `Conv1D`를 쓰려면 `(32, 32×3)`처럼 **가로 방향을 한 시점으로** 묶어 줄 경계가 생기지 않게 해야 합니다.

## 5. `keras68_Conv1D_08_wine.py` — `val_loss`를 `var_loss`로 잘못 적었다

```python
es = EarlyStopping(
    monitor='var_loss',      # ← val_loss 오타
    mode='min',
    patience=10,
    restore_best_weights=True,
)
model.fit(..., epochs=300, batch_size=32, validation_split=0.2, callbacks=[es])
```

작은 데이터로 직접 실행해 확인한 결과입니다.

- 학습이 **예외로 멈추지는 않습니다.** 대신 에폭마다 다음 경고가 찍힙니다.
  `Early stopping conditioned on metric 'var_loss' which is not available. Available metrics are: loss,acc,val_loss,val_acc`
- 감시할 값이 없으니 "좋아졌는지"를 판단하지 못하고, **조기 종료가 한 번도 발동하지 않습니다.** 그래서 `epochs=300`을 끝까지 돕니다(3에폭 시험에서도 3에폭 모두 진행).
- 결과적으로 `restore_best_weights=True`도 의미가 없어집니다(가장 좋았던 시점의 가중치로 되돌릴 근거가 없음).

이 파일의 다른 점검 사항:

- `MaxAbsScaler`가 활성화되어 있고, `MinMaxScaler`·`StandardScaler`·`RobustScaler`는 주석 처리되어 있습니다. 주석 처리된 스케일러를 바꿔 가며 실험하려던 흔적입니다.
- 맨 아래 주석에는 `acc : 1.0`(learning_rate 0.01 실행)과 `acc : 0.3889`(`z_evaluate` 출력)가 함께 있습니다. 같은 파일이라도 **학습이 제대로 됐는지에 따라 결과가 크게 달라진다**는 것을 보여 주는 기록입니다. 두 값 모두 이번에 재현하지 않았습니다.
- `y = pd.get_dummies(y, dtype=int)`로 라벨을 정수 원-핫으로 만듭니다(`10_digits`는 `dtype`을 안 써서 `bool`).

## 6. 기초: NumPy `reshape`의 순서와 `행 × 28 + 열`

`reshape`는 값을 **행 우선**으로, 즉 왼쪽 위부터 오른쪽으로, 한 줄이 끝나면 다음 줄로 채웁니다.

```python
import numpy as np
a = np.arange(6).reshape(2, 3)   # [[0,1,2],[3,4,5]]
a.reshape(-1)                    # [0,1,2,3,4,5]
```

그래서 28×28 그림에서 `(행 r, 열 c)`는 편 배열의 `r*28 + c`번째에 있습니다.

```python
img = np.arange(28*28).reshape(28, 28)
img[5, 3]           # 143
img.reshape(-1)[143] # 143  (5*28+3)
```

- 32×32라면 `r*32 + c`입니다. `(5, 3)`은 `163`번째입니다. **한 줄 길이가 28인지 32인지에 따라 같은 위치의 번호가 달라집니다.**
- `reshape(-1, 64, 1)`의 `-1`은 "나머지 숫자는 알아서 계산해라"라는 뜻입니다. `(1257, 64)`를 `(-1, 64, 1)`로 바꾸면 `(1257, 64, 1)`이 됩니다. 전체 원소 수가 맞지 않으면 `ValueError`가 납니다.

## 7. 반드시 기억할 점

1. `Conv1D` 입력은 항상 `(샘플, 시점, 특징)`. 이미지는 **무엇을 시점으로 삼았는지**를 먼저 확인해야 합니다.
2. `reshape`는 행 우선. 줄 경계(28의 배수, 32의 배수)에서 커널이 서로 먼 픽셀을 이웃으로 볼 수 있습니다.
3. `GAP`는 위치 정보를 지웁니다. 같은 데이터에서 `GAP` 0.4333 vs `Flatten` 0.9389였습니다.
4. `Conv1D` 파라미터는 시점 수와 무관, `(커널×입력채널+1)×필터`.
5. `EarlyStopping`의 `monitor` 이름이 틀리면 **경고만 찍고 조기 종료가 안 됩니다.** 학습이 오래 걸린다면 이 오타를 먼저 의심하세요.
6. `fit`은 훈련 데이터에만. `OneHotEncoder`도 마찬가지입니다(`fit` → `transform`).
7. 이미지에는 `Conv2D`가 기본값입니다. `Conv1D`는 "시간처럼 한 방향으로만 이웃이 의미 있을 때" 씁니다.
