## 1. 시계열을 창(window)으로 자른다 (`keras2/keras66_jena_CNN.py`)

이 파일은 예나(Jena) 기후 데이터로 **앞 144개 시점을 보고, 그다음 144개 시점의 기온을 맞히는** 문제를 풉니다.

```python
x_data = datasets[:-288].drop(['T (degC)'], axis=1).to_numpy(dtype=np.float32)
y_data = datasets[144: -144]['T (degC)'].to_numpy(dtype=np.float32)

def split_x(dataset, size):
    aaa = []
    for i in range(len(dataset) - size + 1):
        aaa.append(dataset[i : (i+size)])
    return np.array(aaa)
```

- `split_x`는 "맨 앞에서부터 한 칸씩 밀면서 `size`개씩 잘라 담는" 함수입니다. 420,263줄에서 144개씩 자르면 창의 개수는 `420263 - 144 + 1 = 420,120`개입니다. (실제 계산으로 확인)
- **정렬이 아주 중요합니다.** `y_data`는 `datasets[144:-144]`라서 **144줄 뒤에서 시작**합니다. 그래서 입력 창 `i`(원본 0~143줄)에 대응하는 정답 창은 **바로 그다음 144줄(144~287줄)** 이 됩니다. 즉 "지금부터 144개를 보고 → 다음 144개를 맞히기"가 됩니다. 합성 데이터로 확인한 결과도 같았습니다: `x창0 = 0~143줄`, `y창0 = 144~287줄`.
- 만약 `y_data`를 `datasets[:-288]`로 만들었다면 정답이 입력과 **같은 시점**이 되어 "미래 맞히기"가 아니라 "지금 값 베끼기"가 됩니다. 숫자 몇 줄 차이로 문제 자체가 달라집니다.
- `for i in range(len(dataset) - size + 1)`에서 `+1`을 빼면 **마지막 창 하나**가 사라집니다. 창의 개수 공식은 항상 `전체 길이 - 창 크기 + 1`입니다.
- `np.array(aaa)`는 `aaa`(리스트)를 하나의 3차원 배열로 합칩니다. 리스트 안에 배열이 420,120개 들어 있으므로 이 순간 메모리가 크게 늘어납니다.

확인된 모양의 흐름입니다(코드 주석 값과 일치).

| 단계 | 모양 |
|---|---|
| `datasets` (주석 값, 이 환경에서 CSV 없음) | `(420551, 14)` |
| `x_data` = `datasets[:-288]`에서 기온 열 제거 | `(420263, 13)` |
| `y_data` = `datasets[144:-144]['T (degC)']` | `(420263,)` |
| `split_x` 후 | `x (420120, 144, 13)`, `y (420120, 144)` |
| `train_test_split` (기본 25%) | `(315090, 144, 13)` / `(105030, 144, 13)`, `(315090, 144)` / `(105030, 144)` |
| 4차원으로 접은 뒤 | `(420120, 12, 12, 13)` |

- `train_test_split(..., shuffle=False)`를 쓴 점이 좋습니다. 시계열은 **섞으면 안 됩니다.** 섞으면 미래 데이터로 학습하고 과거를 맞히는 셈이 되어 점수가 실제보다 좋게 나옵니다.
- `y`가 `(샘플, 144)`인 것은 "144개 시점을 한꺼번에 맞히는" 문제이기 때문입니다. 그래서 모델의 마지막 층도 `Dense(144)`입니다.

### 메모리도 함께 봐야 합니다

- 4차원 배열 전체는 `420120 × 12 × 12 × 13 = 786,464,640`개이고, `float32`이므로 약 **2.93 GiB**입니다. 게다가 스케일링하려고 펴면 `45,372,960 × 13`짜리 배열이 하나 더 생깁니다(역시 약 **2.2 GiB**).
- 그래서 파일 맨 위에 `os.environ["TF_GPU_ALLOCATOR"] = "cuda_malloc_async"` 와 "메모리 터질 때 이거 하면 메모리를 모아서 안 터질 수도 있다"는 주석이 있습니다. 다만 이 환경은 GPU가 없어 이 설정이 실제로 도움이 되는지는 확인하지 못했습니다(추론).

## 2. 시계열을 12×12 "그림"으로 접는다 — 그리고 왜 잘 안 되는가

```python
x_data = x_data.reshape(-1, 12, 12, 13)     # (N, 144, 13) -> (N, 12, 12, 13)
model.add(Conv2D(36, (4, 4), input_shape=(12, 12, 13)))
```

- 왜 될까요? 한 샘플의 숫자 개수가 `144 × 13 = 1,872`, 바꾼 뒤도 `12 × 12 × 13 = 1,872`으로 같기 때문입니다(`Reshape`와 같은 원리).
- 실제로 확인한 대응 규칙은 **`t = 12 × i + j`** 입니다. 12×12 격자의 `(i, j)` 칸이 **시간 `t`번째 시점**, 채널 13개가 **그 시점의 특징 13개**입니다. 즉 "채널 = 특징"이 되는 것은 맞습니다.
- 그런데 **2차원 이웃이 시간 이웃과 같지 않습니다.** `(0,0)→(0,1)`은 시간 0→1로 연속이지만, `(0,1)→(1,0)`은 시간 1→12로 **11칸이나 벌어집니다**. `Conv2D((4,4))`는 이렇게 **서로 12칸씩 떨어진 시점들을 한 창으로 묶어** 봅니다. 그래서 "옆 칸 = 옆 시점"이라는 합성곱의 장점이 거의 사라집니다.
- 결론: **시계열에는 `Conv1D`가 자연스럽습니다.** 이 파일은 "일단 4차원으로 접어 Conv2D를 통과시켜 보라"는 연습이고, 결과도 좋지 않습니다(아래 5·6절).
- 참고로 144는 `12 × 12`로 정확히 나누어떨어지기 때문에 이 접기가 가능했습니다. 144를 13×11처럼 나누어떨어지지 않는 수로 접으면 원소 개수가 맞지 않아 오류가 납니다.

## 3. 4차원 데이터에 `MinMaxScaler` 적용하기

`MinMaxScaler`는 2차원 표만 받습니다. 그래서 **펴서 스케일링하고, 다시 접습니다.**

```python
x_train_scaler = x_train.reshape(-1, x_train.shape[-1])   # (315090,12,12,13) -> (45372960, 13)
scaler = MinMaxScaler()
scaler.fit(x_train_scaler)                                 # 학습 데이터로만 기준 만들기
x_train_scaler = scaler.transform(x_train_scaler)
x_test_scaler  = scaler.transform(x_test_scaler)           # 같은 기준으로 테스트 변환
x_train = x_train_scaler.reshape(x_train.shape)            # 원래 모양으로 되돌리기
```

- `reshape(-1, x_train.shape[-1])`의 뜻: "**마지막 축(13개 특징)은 그대로 두고, 앞의 모든 축은 한 줄로 펴라**". 그래서 `(315090, 12, 12, 13)` → `(45372960, 13)`이 됩니다(실제 계산 확인).
- `fit`은 **학습 데이터에만** 합니다. 테스트 데이터로 기준을 만들면 시험 문제를 미리 보고 범위를 정하는 셈입니다.
- 되접기는 `reshape(x_train.shape)`처럼 **원래 모양을 그대로 넣어** 합니다. 펴는 순서와 접는 순서가 같아서 값이 제자리로 돌아옵니다(합성 데이터로 왕복 확인: 최솟값 0.0, 최댓값 1.0).
- 테스트 데이터에는 학습 데이터 범위를 벗어난 값이 있을 수 있습니다. 그러면 변환 결과가 0보다 작거나 1보다 커집니다. 이것은 **오류가 아니라 정상**입니다(합성 데이터에서 실제로 0~1 밖의 값이 나왔습니다).

## 4. 층별 모양과 파라미터

같은 구조의 모델을 실제로 만들어 확인한 값입니다.

| 층 | 출력 모양 | 파라미터 계산 |
|---|---|---|
| `Conv2D(36,(4,4))` | `(None, 9, 9, 36)` | `4×4×13×36 + 36 = 7,524` |
| `Dropout(0.3)` | `(None, 9, 9, 36)` | 0 |
| `Conv2D(48,(2,2))` | `(None, 8, 8, 48)` | `2×2×36×48 + 48 = 6,960` |
| `Dropout(0.2)` | `(None, 8, 8, 48)` | 0 |
| `Conv2D(24,(2,2))` | `(None, 7, 7, 24)` | `2×2×48×24 + 24 = 4,632` |
| `GlobalAveragePooling2D()` | `(None, 24)` | 0 |
| `Dense(128, relu)` | `(None, 128)` | `24×128 + 128 = 3,200` |
| `Dropout(0.4)` | `(None, 128)` | 0 |
| `Dense(28, relu)` | `(None, 28)` | `128×28 + 28 = 3,612` |
| `Dense(144, relu)` | `(None, 144)` | `28×144 + 144 = 4,176` |
| **합계** | | **30,104** |

- `12 → 9`는 `12 - 4 + 1`, `9 → 8`, `8 → 7`은 `-2+1`입니다(padding 없음).
- `GlobalAveragePooling2D`는 `(7,7,24)`의 7×7 칸을 **채널마다 평균** 내어 `(24,)`로 만듭니다. `Flatten`을 쓰면 `7×7×24 = 1,176`개가 되어 파라미터가 훨씬 커집니다.

## 5. 회귀에 `metrics=['acc']` → 의미 없는 숫자

```python
model.compile(loss='mse', optimizer='adam', metrics=['acc'])
```

- 이 문제는 기온(연속된 숫자)을 맞히는 **회귀**입니다. `acc`는 "정답 클래스를 몇 개 맞혔나"를 세는 지표라서 쓸 수 없습니다.
- 억지로 계산하면 **소수점까지 정확히 같은 값**의 비율을 셉니다. 그런 값은 거의 없으니 0 근처에 머뭅니다. 같은 구조의 모델을 합성 데이터로 3에폭 학습해 확인한 값은 `acc 0.0087 → 0.0109 → 0.0087`이었습니다. 파일 주석의 `acc : 0.0383`도 같은 성격의 숫자입니다.
- `model.evaluate`는 컴파일할 때 적은 순서대로 `[loss, acc]`를 돌려줍니다. 그래서 `loss[0]`은 `mse`, `loss[1]`은 의미 없는 `acc`입니다.
- 회귀에서는 `metrics=['mae']`를 쓰거나, `loss`와 별도로 `RMSE`, `r2_score`를 계산해 보는 것이 맞습니다. 이 파일은 이미 `RMSE`를 직접 함수로 만들어 출력합니다.

### `loss`와 `RMSE`의 관계

- `mse`는 오차를 제곱해 평균 낸 값이고, `RMSE`는 그 값에 루트를 씌운 것입니다. 그래서 `sqrt(76.5041) = 8.7467`이 됩니다(계산 확인). 주석의 `RMSE : 8.74613`과 아주 조금 다른데, `evaluate`의 손실은 배치 단위로 평균을 내서 계산되기 때문에 생기는 미세한 차이입니다(오류로 볼 정도는 아닙니다).
- **RMSE 8.75의 의미**: 정답 기온의 폭이 대략 8~9도 정도라면, 이 모델은 "늘 평균값만 말하는" 수준과 비슷하다는 뜻입니다. 즉 거의 배우지 못했습니다. (실제 예나 데이터의 표준편차는 이 환경에 CSV가 없어 직접 확인하지 못했습니다 — 추론)
- 비교 기준(베이스라인)을 꼭 함께 보세요. 합성 데이터 실험에서는 모델 `RMSE 8.34`가 "항상 학습 평균을 말하기" `RMSE 5.66`보다 **더 나빴습니다**(`r2 = -1.26`). 숫자 하나만 보면 "그럭저럭"처럼 보이지만 기준선보다 못하면 실패입니다.

## 6. 마지막 `Dense(144, activation='relu')`의 치명적 제약

```python
model.add(Dense(144, activation='relu'))    # ← 마지막 층인데 relu
```

- `relu`는 음수를 **0으로 눌러 버립니다**. 그래서 이 모델은 **0도 아래 기온을 절대로 낼 수 없습니다.** 합성 데이터로 확인했을 때 예측값의 최솟값은 정확히 `0.0`이었습니다.
- 기온에는 영하가 있습니다. 영하 값을 0으로만 답하면 아무리 잘 배워도 오차가 남습니다. 회귀의 마지막 층은 **활성화 함수를 쓰지 않는 것(linear)** 이 기본입니다.
- 중간 층의 `relu`는 괜찮습니다. 문제는 **출력층**입니다. "분류의 마지막은 softmax/sigmoid, 회귀의 마지막은 그냥 Dense"로 기억하세요.
- 참고로 출력이 `(샘플, 144)` 2차원인데 `y`도 `(샘플, 144)`라서 짝은 맞습니다(실제 확인: 예측 `(193,144)`, 정답 `(193,144)`).

## 7. 콜백 3종

```python
mcp = ModelCheckpoint(monitor='val_loss', mode='auto', save_best_only=True,
                      filepath="./_save/keras66/kaggle_jena1_{epoch:04d}-{val_loss:.4f}.keras", verbose=1)
rlr = ReduceLROnPlateau(monitor='val_loss', mode='min', patience=50, verbose=1, factor=0.1)
es  = EarlyStopping(monitor='val_loss', mode='min', patience=100, restore_best_weights=True)
model.fit(..., epochs=100000, callbacks=[es, rlr, mcp])
```

- **`EarlyStopping`**: `val_loss`가 `patience`(100)번 연속 좋아지지 않으면 멈춥니다. `restore_best_weights=True`는 멈출 때 **가장 좋았던 가중치로 되돌려** 줍니다. 이게 없으면 마지막(나빠진) 상태가 남습니다.
- **`ModelCheckpoint`**: `save_best_only=True`라서 `val_loss`가 **가장 좋았을 때만** 파일로 저장합니다. 파일 이름의 `{epoch:04d}`는 에포크를 네 자리(0001), `{val_loss:.4f}`는 손실을 소수 넷째 자리까지 적으라는 뜻입니다. 실제로 확인한 파일 이름은 `jena1_0001-1.3762.keras` 형식이었습니다.
- **`ReduceLROnPlateau`**: `val_loss`가 `patience`(50)번 개선되지 않으면 학습률에 `factor`(0.1)를 **곱합니다**(=10분의 1로 줄임). 실제로 평평한 상황을 만들어 확인해 보니 `0.01 → 0.001 → 0.0001 …`처럼 정확히 0.1배씩 줄었습니다. 학습률을 줄이면 마지막에 조금씩 정밀하게 다듬는 효과가 있습니다.
- `epochs=100000`은 "그만큼 하라"는 뜻이 아니라 "**콜백이 멈춰 줄 때까지** 하라"는 뜻입니다. 실제로는 EarlyStopping이 먼저 멈춥니다.

## 8. 코드·주석에서 실제와 다른 곳

1. **예측용 데이터의 열 삭제 실수** (가장 중요)

```python
x_predict = datasets[-288:-144].drop(['wd (deg)'], axis=1)   # ← 훈련은 'T (degC)'를 지웠다
x_predict = x_predict.reshape(1, 144, 13)
```

   - 훈련 데이터는 `T (degC)`(정답 기온)를 지웠습니다. 그런데 예측용 데이터는 `wd (deg)`(풍향)를 지웁니다. 그래서 **예측 입력에는 정답 열이 들어 있고, 풍향 열은 빠집니다.** 13개 열이라는 개수만 같을 뿐 **내용이 다릅니다.** 합성 데이터로 확인: `훈련에만 있는 열: ['wd (deg)']`, `예측에만 있는 열: ['T (degC)']`.
   - 게다가 `reshape(1, 144, 13)`은 **3차원**인데 모델은 **4차원 `(12,12,13)`** 을 요구합니다. 실제로 이 모양을 그대로 넣으면 `ValueError: Input 0 of layer "sequential" is incompatible with the layer: expected shape=(None, 12, 12, 13), found shape=(None, 144, 13)`가 납니다(실행 확인). 즉 **이 파일은 예측 단계를 실행하면 실패합니다.** (지금 코드는 `x_predict`로 predict를 하지 않고 `x_test`로만 예측하므로 그 줄이 실행되지 않아 조용히 넘어갑니다.)
   - 또한 `x_predict`는 **스케일링도 하지 않습니다.** 스케일러는 학습 데이터로 `fit`했으니, 예측 데이터도 같은 스케일러로 `transform`해야 합니다.
2. `y_cor = datasets[-144:]['T (degC)']`는 **만들어만 두고 쓰지 않습니다.** 그래서 "다음 날 144개를 예측해서 실제와 비교"하는 마지막 단계가 없습니다.
3. 회귀에 `metrics=['acc']` (5절) — 주석의 `acc : 0.0383`은 의미 없는 숫자입니다.
4. 마지막 층 `relu` (6절) — 영하 기온을 낼 수 없습니다.
5. `y (420120, 144)`를 `split_x`로 또 잘랐기 때문에 메모리가 두 배로 듭니다. `size_y = 144`면 `split_x` 대신 그냥 필요한 구간을 잘라 쓰는 방법도 있습니다(추론).

## 쉬운 예시로 정리

- **창 자르기**: 20칸짜리 종이를 5칸 창으로 보는 것. 창을 한 칸씩 옮기면 볼 수 있는 위치는 `20-5+1 = 16`곳입니다. `+1`을 잊으면 마지막 한 곳을 못 봅니다.
- **정답 정렬**: "1일~5일을 보고 6일~10일을 맞히기". 입력과 정답을 같은 구간에서 자르면 "1일~5일을 보고 1일~5일을 맞히기"가 되어 정답을 그대로 베끼는 문제가 됩니다.
- **12×12 접기**: 144명을 12줄×12칸 교실에 앉히는 것. 짝꿍(옆자리)은 원래 줄에서 바로 옆이지만, 줄이 바뀌면 12칸 떨어진 사람이 됩니다. 그래서 "옆 사람과 이야기하기(합성곱)"가 원래 뜻대로 되지 않습니다.
- **`(7,7,24)` → `(24,)`**: 24과목 성적표에서 7×7칸을 다 더하지 않고 **과목별 평균**만 내는 것(`GlobalAveragePooling`).
- **`relu` 출력층**: "0보다 작은 답은 절대 말하지 마"라고 규칙을 정한 것과 같습니다. 영하를 답해야 하는 문제에는 맞지 않습니다.
- **`ReduceLROnPlateau`**: 목표 지점 근처에서 발걸음을 10분의 1로 줄이는 것. 멀리서는 크게, 가까이서는 조금씩.

## 반드시 기억할 점

- 창 개수 = `전체 길이 - 창 크기 + 1`. 시계열 정답은 입력 **바로 다음** 구간이어야 합니다.
- 시계열은 `shuffle=False`로 나눕니다.
- `(N,144,13)` → `(N,12,12,13)`은 **원소 개수가 같아서** 가능하고, 채널 = 특징, `(i,j)` 칸 = 시간 `12i+j`입니다. 2차원 이웃 ≠ 시간 이웃이라 Conv2D에는 불리합니다(시계열에는 `Conv1D`).
- 4차원 스케일링: `reshape(-1, 마지막축)`으로 펴서 `fit`(학습만) → `transform` → `reshape(원래모양)`.
- 회귀에 `acc`는 의미 없습니다. `mse`/`mae`/`RMSE`/`r2`를 봅니다. `sqrt(mse) = RMSE`.
- **회귀의 마지막 층에는 활성화 함수를 쓰지 않습니다**(relu를 쓰면 음수를 못 냅니다).
- `EarlyStopping(restore_best_weights=True)`는 최고 상태로 되돌립니다. `ModelCheckpoint(save_best_only=True)`는 최고일 때만 저장합니다. `ReduceLROnPlateau(factor=0.1)`은 학습률을 10분의 1로 줄입니다.
- 항상 **베이스라인**(평균만 말하기)과 비교합니다. 그보다 나쁘면 배우지 못한 것입니다.
