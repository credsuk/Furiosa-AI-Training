## 중요한 내용

### 1. RAG의 기본 흐름

코드의 큰 흐름은 `문서 로딩 → 청킹 → 임베딩 → 벡터 저장 → 질문과 가까운 문서 검색 → context를 prompt에 넣기 → 모델 답변 → Gradio 화면 연결`입니다. `k=2`는 질문과 가까운 문서 조각을 2개 가져오도록 정하는 값입니다. 검색기가 답을 직접 만드는 것이 아니라, 관련 문서를 골라 다음 체인에 전달합니다.

`PyPDFLoader`는 PDF를 읽어 페이지별 `Document` 목록으로 만들고, `HuggingFaceEmbeddings`는 문장 하나를 숫자 배열로 바꿉니다. `BAAI/bge-m3`와 `Qwen/Qwen3-Embedding-0.6B`의 주석상 벡터 차원은 1024이지만, 이 숫자는 실제 해당 모델을 현재 환경에서 실행해 확인한 결과가 아니라 코드 주석에 적힌 기대값입니다.

### 2. FAISS와 안전한 로딩

`FAISS.from_documents()`는 문서와 임베딩을 이용해 검색용 인덱스를 만들고 `save_local()`로 저장합니다. `load_local()`은 저장된 인덱스를 다시 읽습니다. `allow_dangerous_deserialization=True`는 pickle 기반 데이터를 읽는 것을 허용하는 옵션이므로, 출처를 신뢰할 수 있는 저장 파일에만 사용해야 합니다. 이 옵션이 파일을 안전하게 바꿔 주는 것은 아닙니다.

### 3. Keras 다중 입력

`keras69_ensemble1.py`의 입력은 `(100, 2)`와 `(100, 3)`이고, `keras69_ensemble2.py`에는 `(100, 4)` 입력이 하나 더 있습니다. 첫 번째 축 100은 같은 100개 샘플을 뜻하고, 뒤의 숫자는 각 샘플의 feature 수입니다. `train_test_split(x1, x2, x3, y)`처럼 함께 전달하면 같은 행이 함께 섞여 학습·테스트로 나뉩니다. 입력이나 정답의 순서가 따로 섞이면 서로 다른 샘플의 데이터가 연결되어 학습이 망가집니다.

각 입력 가지는 Dense 층을 거친 뒤 `Concatenate`로 붙습니다. 예를 들어 `(batch, 80)`, `(batch, 40)`, `(batch, 40)`을 마지막 축으로 연결하면 `(batch, 160)`이 되고, 그 뒤 Dense 층을 지나 최종 출력이 됩니다.

### 4. Keras 다중 출력과 계산 그래프

`keras69_ensemble3.py`는 `outputs=[last_output1, last_output2]`인 모델입니다. 따라서 `fit()`과 `evaluate()`의 정답도 `[y1, y2]` 순서로 넣어야 합니다. `last_dense1`, `last_dense2`는 만들어졌지만 `last_output1`에 연결되지 않았습니다. 실제 출력에 사용하려면 예를 들어 `last_output1 = Dense(1, name="last1")(last_dense2)`처럼 계산 경로에 연결해야 합니다. 현재 코드에서 `last_output1 = Dense(1)(merge3)`이므로 두 Dense 층은 최종 출력 계산에 참여하지 않습니다.

## 반드시 기억할 점

- 주석의 loss·predict·임베딩 차원은 실행 기록일 수 있지만, 현재 환경의 재현 결과와 같은 뜻은 아니다.
- 여러 입력과 정답은 같은 샘플 행 순서를 유지해야 한다.
- `Concatenate`는 지정한 축으로 배열을 이어 붙이며, feature 축을 이어 붙이는 경우 feature 수가 더해진다.
- 다중 출력 모델의 출력 순서와 정답 순서는 반드시 맞아야 한다.
- 코드에 층을 적었다는 사실만으로 계산 그래프에 연결된 것은 아니다.
- `axis=1`은 DataFrame의 열 방향을 뜻하므로 `df.drop([target], axis=1)`은 target 열을 제거한다.
- `allow_dangerous_deserialization=True`는 신뢰할 수 있는 파일이라는 전제가 필요하다.

## 코드 흐름과 shape 설명

1. NumPy로 100개 샘플의 입력 배열을 만들고 `.T`로 `(feature 수, 100)`을 `(100, feature 수)`로 바꾼다.
2. `train_test_split`에 입력 배열들과 y를 함께 넣어 90% 학습, 10% 테스트로 나눈다. `test_size=0.1`이라는 설정과 실제 실행 결과는 코드 구조로 확인했지만 학습 실행은 하지 않았다.
3. 각 `Input(shape=(feature 수,))`에서 Dense 층을 통과시킨다.
4. 여러 가지의 출력 feature를 `Concatenate`로 합친 뒤 Dense 층과 최종 출력으로 보낸다.
5. 다중 출력 모델은 두 개의 출력 배열을 반환하므로 입력 목록과 정답 목록의 순서를 동일하게 유지한다.
6. RAG에서는 PDF 또는 텍스트를 `Document`로 만들고, 청크를 임베딩해 FAISS/Chroma에 저장한 뒤 retriever가 `k`개 문서를 골라 `{context}`에 넣는다.

## 쉬운 예시

학생 100명의 정보를 두 공책에 나누어 적었다고 생각해 봅시다. 첫 번째 공책에는 국어·수학 2개 점수, 두 번째 공책에는 과학·영어·체육 3개 점수가 있습니다. 1번 학생의 두 공책 정보가 함께 1번 학생을 설명해야 합니다. 공책을 따로 섞으면 1번 학생의 점수와 7번 학생의 점수가 합쳐져 잘못 배웁니다.

RAG는 도서관 사서와 비슷합니다. 질문을 받으면 모든 책을 외우는 대신 질문과 가까운 책 조각을 몇 개 찾아서 답변자에게 건넵니다. `k=2`이면 가까운 조각 2개를 건네는 것입니다. 단, 사서가 찾았다는 것과 답변자가 실제로 답을 잘 만들었다는 것은 별도로 확인해야 합니다.
