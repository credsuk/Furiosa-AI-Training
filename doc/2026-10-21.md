## 주제

오늘은 LangGraph에서 그래프를 시각화하고, 대화 기억을 유지하며, 두 작업을 동시에 실행한 뒤 결과를 합치는 방법을 학습했다.

1. `draw_mermaid_png()`로 그래프 구조를 PNG 바이트로 만들기
2. `BytesIO`와 `PIL.Image`로 메모리 속 PNG를 이미지로 읽기
3. `InMemorySaver`와 `thread_id`로 같은 대화 흐름의 상태를 저장하기
4. `START`에서 여러 노드로 엣지를 연결해 병렬 작업 만들기
5. 여러 작업이 끝난 뒤 `merge` 노드에서 결과를 합치기
6. 검색 결과와 모델 분석 결과를 하나의 최종 메시지로 만들기

## 중요한 내용

- 그래프를 실행하는 것과 그래프 그림을 만드는 것은 별개의 작업이다. `draw_mermaid_png()`는 그래프의 연결 구조를 PNG 데이터로 만들 뿐, 모델 호출이나 검색을 대신하지 않는다.
- `lg07_ToolNode_graph01.py`는 PNG 바이트를 `_save/image/lg07_ToolNode.png`에 저장한다. 대상 디렉터리가 없으면 `open()`에서 실패할 수 있다.
- `lg07_ToolNode_graph02.py`는 PNG를 `BytesIO`로 감싸 `PIL.Image.open()`으로 이미지 객체로 읽고, `matplotlib`으로 화면에 표시한다. 실제 화면 표시 성공 여부는 GUI 실행 환경이 필요하다.
- `lg08_Memory01.py`의 두 `graph.invoke()` 호출은 각각 새 입력을 넘기므로, 기본 컴파일만으로 두 호출의 이전 메시지가 자동으로 이어진다고 단정할 수 없다.
- `lg08_Memory02.py`는 `InMemorySaver`를 `checkpointer`로 연결하고 같은 `thread_id`인 `user01`을 두 번 사용한다. 이 설정이 있어야 같은 대화 스레드의 상태를 이어서 조회할 수 있다.
- `InMemorySaver`는 프로그램이 실행되는 동안 메모리에 저장하는 방식이다. 프로그램을 종료하면 영구 데이터베이스처럼 보존된다고 보면 안 된다.
- 병렬 그래프는 `START → search`와 `START → analysis`처럼 시작점에서 여러 작업으로 나뉜다. 두 작업의 결과가 모두 필요한 `merge`에는 두 노드에서 엣지를 연결한다.
- `lg09_병렬실행_병합1.py`는 `State`에 `question`을 선언했지만 실행 입력에는 `questring`을 넣는 오타가 있다. 현재 함수가 입력 질문을 직접 읽지 않아 해당 예제의 일부 흐름은 진행될 수 있어도, 상태 키 계약은 깨져 있으므로 수정해야 한다.
- 외부 검색·LLM·그래프 PNG·matplotlib 실행은 패키지 설치, 환경변수, 네트워크, GUI 조건에 의존한다. 코드에 적힌 예상 문장이나 주가를 실제 실행 결과로 기록하지 않는다.

## 코드 흐름과 shape 설명

1. 그래프 시각화 예제는 `StateGraph`를 컴파일한 뒤 `graph.get_graph().draw_mermaid_png()`을 호출한다.
2. `lg07_ToolNode_graph01.py`의 반환값은 PNG 파일에 쓸 수 있는 바이트 데이터다. `'wb'`는 바이너리 쓰기 모드다.
3. `lg07_ToolNode_graph02.py`에서는 `BytesIO(png_data)`가 바이트를 파일처럼 보이게 하고, `Image.open()`이 이미지 객체로 읽는다. `plt.imshow()`는 그 이미지를 화면에 배치한다.
4. 메모리 예제의 `State`는 `messages` 리스트를 가지고 있다. `InMemorySaver`는 그래프 실행 상태를 `thread_id`별로 저장한다.
5. 병렬 병합 예제의 상태 모양은 `question`, `search_result`, `analysis_result`, `final_result` 또는 두 결과와 `messages`이다. `search_agent`와 `analysis_agent`가 서로 다른 상태 키를 만들고 `merge_agent`가 두 값을 읽는다.
6. `lg09_병렬실행_병합2.py`에서는 검색 에이전트가 검색 결과를 문자열로 만들고, 분석 에이전트가 모델 응답을 문자열로 만든다. 병합 에이전트는 두 문자열을 줄바꿈과 구분선으로 연결해 assistant 메시지로 반환한다.

## 쉬운 예시

- 그래프 그림: 레고 블록으로 만든 길을 사진 찍는 것과 같다. 사진은 길을 보여 주지만 블록이 자동으로 움직이지는 않는다.
- 메모리: 공책에 `user01`이라는 이름표를 붙이는 것과 같다. 같은 이름표로 다시 찾으면 앞에서 적은 대화를 이어 볼 수 있다.
- 병렬 실행: 한 사람은 자료를 찾고 다른 사람은 생각하게 한 뒤, 마지막 사람이 두 결과를 한 장의 보고서로 합치는 것과 같다.

## 반드시 기억할 점

- PNG 바이트와 이미지 객체와 화면 출력은 서로 다른 단계다.
- `InMemorySaver`만 만든다고 기억이 연결되는 것이 아니다. `compile(checkpointer=memory)`와 같은 `thread_id`가 함께 필요하다.
- 병렬 작업의 결과를 합치는 노드는 각 결과가 저장된 정확한 상태 키를 읽어야 한다.
- `question`과 `questring`처럼 상태 키가 다르면 선언한 데이터 계약과 실제 입력이 달라진다.
- 실행하지 않은 외부 API 응답과 GUI 결과를 성공했다고 쓰지 않는다.
