## 중요한 내용과 코드 흐름

### 1. 컴퓨터는 글자를 계산하지 못한다 (`keras2/keras60_Tokenizer1.py`)

```python
text = "나는 지금 진짜 진짜 매우 매우 맛있는 김밥을 엄청 마구 마구 마구 마구 먹었다."
token = Tokenizer()          # 1) 도구(객체)를 만든다
token.fit_on_texts([text])   # 2) 문장을 읽고 단어 사전을 만든다
token.texts_to_sequences([text])  # 3) 문장을 단어 번호 목록으로 바꾼다
```

- `fit_on_texts`는 "단어를 세어서 번호를 붙이는" 단계입니다. 이때 **자주 나온 단어에 작은 번호**를 줍니다. 이 문장에서는 `마구`가 4번 나와서 1번, `진짜`·`매우`가 2번씩 나와서 2·3번, 나머지 한 번 나온 단어가 4번부터 붙습니다.
- 번호 0은 **비워 둡니다**. 0은 나중에 `pad_sequences`가 "빈칸"을 채울 때 쓰는 값이기 때문입니다. 그래서 실제 단어 번호는 1부터 시작합니다.
- `texts_to_sequences`의 결과는 `[[4, 5, 2, 2, 3, 3, 6, 7, 8, 1, 1, 1, 1, 9]]`처럼 **리스트 안에 리스트**입니다. 문장이 여러 개일 수 있어서 한 겹 더 감싸기 때문입니다. 그래서 원-핫 인코딩 전에 `np.array(x).reshape(-1)`로 1차원으로 폅니다.
- 원-핫 인코딩 결과의 열 수가 도구마다 다릅니다. 실제로 실행해 보니 같은 14개 번호(1~9)에 대해 **pandas `get_dummies`·sklearn `OneHotEncoder`는 9열**, **`to_categorical`은 10열**이었습니다. `to_categorical`은 "관측된 값"이 아니라 **0부터 최댓값(9)까지 전부**를 클래스로 세기 때문입니다. 0번 자리(빈칸)까지 열이 생기는 것이 차이입니다.

### 2. 길이가 달라서 생기는 문제 (`keras2/keras61_Embedding01_DNN.py`)

15문장의 단어 수는 1개부터 5개까지 제각각입니다. 실제로 실행한 결과 길이는 `[2, 2, 3, 3, 5, 1, 1, 2, 2, 1, 2, 2, 2, 2, 3]`이었습니다. 신경망은 한 번에 같은 모양의 표를 받아야 하므로 길이를 5로 맞춥니다.

```python
padded_x = pad_sequences(x, padding='pre', maxlen=5, truncating='pre')
# (15, 5)  ← 실행해서 확인
```

- `padding='pre'`: **앞**을 0으로 채웁니다. `'post'`면 뒤를 채웁니다.
- `truncating='pre'`: 5보다 길면 **앞**을 자릅니다. 기본값도 `'pre'`입니다.
- 예: `'참 잘만든 영화에요'` → `[0, 0, 1, 5, 6]`, `'한 번 더 보고 싶어요'`(5단어) → `[10, 11, 12, 13, 14]`, `padding='post'`로 바꾸면 `[1, 5, 6, 0, 0]`.
- `train_test_split(..., test_size=0.1)`에 15개를 넣으면 **테스트 2개, 학습 13개**가 됩니다(1.5 → 올림 2). 실제 실행으로 확인했습니다.
- 예측용 문장도 **학습 때와 똑같은 순서**로 처리해야 합니다: `texts_to_sequences` → `pad_sequences`. `["개똥이 잘생겼다"]`는 `[[24, 27]]` → 패딩 후 `[[0, 0, 0, 24, 27]]`, 모양 `(1, 5)`입니다.

### 3. 숫자 하나 vs 숫자 벡터 (`keras2/keras61_Embedding04_중요.py`)

| 방식 | 생김새 | 특징 |
|---|---|---|
| 원-핫(`to_categorical`) | 5개 단어 × 31칸 = 3차원 | 칸이 아주 많고, 단어끼리 "비슷하다"는 정보가 없음 |
| `Embedding` | 5개 단어 × 10칸 = 3차원 | 표의 숫자를 **학습하면서** 조정. 비슷한 뜻의 단어가 비슷한 벡터가 되도록 배움 |

```python
model.add(Embedding(input_dim=31, output_dim=10, input_length=5))
```

- `input_dim` = 단어 사전 크기(0번 포함). 표의 **행 개수**입니다.
- `output_dim` = 단어 하나를 몇 개 숫자로 표현할지. 표의 **열 개수**입니다.
- 표의 숫자 개수 = `input_dim × output_dim`. 실제로 세어 보니 `31×10 = 310`, `30×10 = 300`이었습니다.
- `input_length=5`는 "문장 길이는 5"라는 정보입니다. 생략해도 되고, `Embedding(30, 10, 5)`처럼 **세 번째 자리에 그냥 숫자를 넣으면 오류**가 납니다. 세 번째 자리는 `input_length`가 아니라 `embeddings_initializer` 자리이기 때문입니다(실행 결과 `ValueError: Could not interpret initializer identifier: 5`).

### 4. LSTM은 3차원을 받는다 (`keras2/keras61_Embedding02_LSTM.py`)

LSTM이 기대하는 모양은 **(문장 개수, 단어 수, 특징 수)** 3차원입니다.

- 이 파일에서 `padded_x`는 `(15, 5)` 2차원이고, `# padded_x = padded_x.reshape(15, 5, 1)` 줄은 **주석 처리**되어 있습니다. 그래서 `print` 옆 주석의 `(13, 5, 1)`은 실제 값이 아닙니다(실제는 `(13, 5)`).
- 이 환경(keras 2.15.1)에서 2차원을 그대로 `fit`에 넣어 보니 **오류 없이 지나갔습니다**. keras가 특징 1개로 해석한 경우입니다. 그러나 같은 프로세스에서 2차원으로 예측한 뒤 3차원으로 다시 예측하니 `TypeError: 'NoneType' object is not subscriptable`가 났습니다. **모양을 섞어 쓰면 위험**하므로 `reshape(15, 5, 1)`처럼 명시하는 편이 안전합니다.

### 5. 검증에서 확인한 "주석과 실제가 다른 곳" 4가지

1. `keras61_Embedding02_LSTM.py` 46행 주석 `(13, 5, 1)` → 실제는 `(13, 5)` (reshape가 주석 처리됨)
2. `keras61_Embedding03_ohe_LSTM.py` 56행 주석 `(13, 35)` → 실제는 `(13, 5, 31)` (`to_categorical`이 (15,5,31)을 만들기 때문)
3. `keras61_Embedding01_DNN.py` 116행 주석 `(1, 2)` → 실제는 `(1, 5)` (`maxlen=5`로 패딩했으므로)
4. `keras61_Embedding01_DNN.py` 128행 주석 `y_predict :: [[-0.12053862]]` → 마지막 층이 `sigmoid`라면 **음수가 나올 수 없습니다**. 실제로 sigmoid 모델을 돌려 보면 0과 1 사이 값만 나왔습니다. 이 주석은 sigmoid를 쓰기 전(또는 다른 설정) 결과로 보입니다.

그리고 `keras61_Embedding03_ohe_LSTM.py`에는 **예측 단계에서 실제로 오류가 나는 문제**가 있습니다.

```python
x_predict = pad_sequences(token.texts_to_sequences(["개똥이 잘생겼다"]), maxlen=5)  # (1,5) = [[0,0,0,24,27]]
x_predict = to_categorical(x_predict)   # (1, 5, 28)  ← 31이 아님!
model.predict(x_predict)                # Matrix size-incompatible: In[0]: [1,28], In[1]: [31,80]
```

학습 데이터에는 30번 단어까지 있어서 31칸이었는데, 예측 문장의 최댓값은 27번이라 `to_categorical`이 28칸짜리를 만듭니다. 해결은 간단합니다: `to_categorical(x_predict, num_classes=31)`로 칸 수를 고정하면 `(1,5,31)`이 되고 정상 예측됩니다(실행 확인).

### 6. 두 갈래 분류에서 자주 틀리는 두 가지 (`keras2/keras62_2_imdb.py`)

- `Dense(2, activation='sigmoid')` + `binary_crossentropy`: 출력 두 개가 **서로 독립**입니다. 실제로 돌려 보면 한 행의 두 값 합이 `1.056`, `1.206`, `0.284`처럼 제각각이었습니다. 두 갈래 중 하나를 고르려면 `Dense(2, activation='softmax')`(합이 정확히 1.0) 또는 `Dense(1, activation='sigmoid')` + 0/1 정답을 씁니다.
- `model.evaluate(x_train, y_test)`: x는 학습 데이터, y는 테스트 정답이라 **짝이 맞지 않습니다**. 두 배열 길이가 같아 오류는 안 나지만, 그 숫자는 아무 의미가 없습니다. `evaluate(x_test, y_test)`가 맞습니다.
- `keras62_1_reuters.py`의 `Embedding(np.max(x_train_padding), 1500)`도 같은 종류의 실수입니다. `num_words=2000`이면 단어 번호는 1~1999이므로 `input_dim`은 2000 이상이어야 하는데, 최댓값(1999)을 그대로 넣어 **표가 한 칸 모자랍니다**. (이 파일은 전체 학습에 시간이 걸려 실행하지 않았고, 아래 5번에서 확인한 `Embedding(30, …)` 사례로 같은 원리를 확인했습니다.)
- 두 파일의 `maxlen` 주석도 오래된 값입니다: 62_1은 `maxlen=300`인데 주석은 `(8982, 200)`, 62_2는 `maxlen=700`인데 주석은 `(25000, 800)`입니다.

## shape와 쉬운 예시

문장 `'참 잘만든 영화에요'`가 모델까지 가는 길을 표로 보면 이렇습니다.

| 단계 | 결과 | shape |
|---|---|---|
| 원문 | `'참 잘만든 영화에요'` | 글자 |
| `texts_to_sequences` | `[1, 5, 6]` | 길이 3 |
| `pad_sequences(maxlen=5)` | `[0, 0, 1, 5, 6]` | `(5,)` |
| 15문장 묶음 | 15행 | `(15, 5)` |
| `to_categorical` | 단어마다 31칸 | `(15, 5, 31)` |
| `Embedding(31, 10)` | 단어마다 10칸 | `(15, 5, 10)` |

쉬운 비유: 단어 번호는 **사물함 번호**입니다. `pad_sequences`는 사물함이 5칸인 줄에 맞춰 앞을 빈칸(0)으로 채우는 일이고, `Embedding`은 사물함마다 **10개의 손잡이(숫자)** 를 붙여 "이 단어는 저 단어와 닮았다"를 숫자로 표현하는 일입니다. 원-핫은 사물함 31개 중 하나만 불을 켜는 방식이라 손잡이가 31개인 셈입니다.

## 반드시 기억할 점

- `Tokenizer`의 0번은 빈칸용으로 비어 있고, 단어 번호는 **1부터** 시작합니다.
- `word_index`는 **자주 나온 단어가 작은 번호**를 받습니다. 같으면 먼저 나온 단어가 앞섭니다.
- 학습 때와 예측할 때 **똑같은 전처리 순서**(`texts_to_sequences` → `pad_sequences` → 원-핫/임베딩)를 써야 합니다.
- `Embedding`의 `input_dim`은 **최댓값이 아니라 단어 수(+1)** 입니다. 모자라면 `indices[i] = 30 is not in [0, 30)` 오류가 납니다.
- `to_categorical`은 **그때 들어온 값의 최댓값**으로 열 수를 정합니다. 예측할 때는 `num_classes`를 꼭 고정하세요.
- LSTM 입력은 **(개수, 시간, 특징)** 3차원입니다.
- 두 갈래 분류: `Dense(2)`면 `softmax`, `Dense(1)`이면 `sigmoid`입니다. 섞으면 확률 합이 1이 되지 않습니다.
