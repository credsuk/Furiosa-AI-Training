## 1. 표 데이터를 `Conv1D`에 넣는다는 것

`Conv1D`는 원래 "시간 순서가 있는 값"을 보는 층입니다. 입력은 `(샘플, 시점, 특징)` 3차원이고, 커널이 **시점 축을 따라** 한 칸씩 움직입니다.

그런데 다이아베테스 데이터는 특징이 10개(나이, 성별, BMI 같은 값)이고 시간 순서는 없습니다. 이 파일은 그 10개 특징을 **억지로 "시점 10개"처럼** 취급합니다.

```python
x_train = x_train.reshape(-1, 10, 1)   # (331, 10) -> (331, 10, 1)
model.add(Conv1D(32, (2,), input_shape=(10,1)))
```

- `(331, 10, 1)`은 "샘플 331개, 각 샘플은 시점 10개, 각 시점의 특징 1개"라는 뜻입니다.
- 즉 **특징 하나가 시점 하나**가 되었습니다. 이제 커널 2는 "첫 번째 특징과 두 번째 특징을 이웃으로 본다"고 계산합니다.
- 하지만 나이와 성별이 "이웃"이라는 건 시간처럼 자연스러운 관계가 아닙니다. 그래서 표 데이터에 `Conv1D`를 쓰는 것은 **공부용 실험**이지, 보통 성능이 좋아져서 쓰는 방법은 아닙니다.

## 2. `keras68_Conv1D_02_diabetes.py` — 층별 모양과 파라미터

실제로 모델을 만들어 확인한 값입니다.

| 층 | 출력 모양 | 파라미터 계산 | 파라미터 |
|---|---|---|---|
| `Conv1D(32, (2,))` | `(None, 9, 32)` | `(2×1+1)×32` | 96 |
| `Conv1D(64, (2,))` | `(None, 8, 64)` | `(2×32+1)×64` | 4,160 |
| `Flatten()` | `(None, 512)` | 없음 (`8×64=512`) | 0 |
| `Dense(23)` | `(None, 23)` | `512×23+23` | 11,799 |
| `Dense(14)` | `(None, 14)` | `23×14+14` | 336 |
| `Dense(1)` | `(None, 1)` | `14×1+1` | 15 |
| **합계** | | | **16,406** |

- 시점 길이는 `10 → 9 → 8`로 줄어듭니다(커널 2, `padding` 없음 → `길이-커널+1`).
- 10-28에서 배운 공식이 여기서도 그대로입니다. `Conv1D` 파라미터는 **시점 개수와 무관**하고 `(커널×입력채널+1)×필터`로만 정해집니다.

### 활성화 함수가 하나도 없다

이 파일에는 `activation=`이 **한 군데도 없습니다.** `Conv1D`, `Dense` 모두 기본값이 `linear`입니다.

- `Conv1D`는 원래부터 선형 계산(곱하고 더하기)입니다. `Dense`도 `activation`을 안 주면 선형입니다.
- 선형 함수를 여러 개 이어 붙이면 **결국 하나의 선형 함수**가 됩니다. `2(3x) = 6x`처럼 순서를 바꿔도 같은 모양이기 때문입니다.
- 그래서 이 6층짜리 신경망은 사실상 "입력 10개에 가중치를 곱해 더하는" 아주 단순한 계산과 비슷합니다.

실제로 확인했습니다(60에폭, 같은 분할·같은 스케일):

| 모델 | 테스트 `r2` |
|---|---|
| 위 신경망(활성화 없음) | 0.4165 |
| `sklearn` `LinearRegression` (선형 회귀 한 줄) | 0.4190 |

- 층을 6개 쌓았는데 성능이 **한 줄짜리 선형 회귀와 거의 같습니다.** 이것이 "활성화 함수가 없으면 깊게 쌓아도 의미가 없다"는 증거입니다.
- 파일 주석의 `r2 : 0.408`도 같은 이유로 낮게 나온 것으로 보입니다(주석 값 자체는 재현하지 않았습니다).
- 고치는 방법: `Dense(23, activation='relu')`처럼 층 사이에 비선형 함수를 넣습니다. 그러면 "꺾인 선"을 여러 번 이어 붙일 수 있어 복잡한 관계를 배울 수 있습니다.

### `x_test`가 111개인 이유

`train_test_split(x, y, random_state=34)`처럼 `test_size`를 적지 않으면 기본값 **0.25**가 됩니다. 다이아베테스는 442개이므로 훈련 331개, 테스트 111개입니다(실제 실행 확인). 따릉이 파일도 같은 원리로 `1328 → 996 + 332`가 됩니다.

## 3. `keras68_Conv1D_04_dacon_ddarung.py` — 열 순서가 곧 시간

```python
x_train = x_train.reshape(-1, 3, 3)   # (996, 9) -> (996, 3, 3)
model.add(Conv1D(16, (3,), input_shape=(3,3)))
```

- 특징 9개를 `3 × 3`으로 접었습니다. `reshape`는 값을 **앞에서부터 순서대로** 채우기 때문에, csv의 열 순서가 그대로 "시점 3개 × 특징 3개"가 됩니다.

| 시점 | 들어가는 열 |
|---|---|
| 시점 0 | `hour`, `hour_bef_temperature`, `hour_bef_precipitation` |
| 시점 1 | `hour_bef_windspeed`, `hour_bef_humidity`, `hour_bef_visibility` |
| 시점 2 | `hour_bef_ozone`, `hour_bef_pm10`, `hour_bef_pm2.5` |

- 실제로 `np.arange(9).reshape(1,3,3)`을 해 보면 `[[[0,1,2],[3,4,5],[6,7,8]]]`이 됩니다. 열을 뒤집으면 `[[[8,7,6],[5,4,3],[2,1,0]]]`이 됩니다.
- 그래서 **열 순서를 바꾸면 모델이 보는 이웃이 달라집니다.** 가중치를 `[[1,2],[3,4],[5,6]]`으로 고정하고 확인해 보니, 같은 데이터라도

| 입력 | 합성곱 출력 |
|---|---|
| 열 순서 그대로 | `[70, 133]` |
| 열 3개 순서를 뒤집음 | `[62, 125]` |

- 값이 달라졌습니다. 시계열에서는 "옆 시점"이 자연스러운 이웃이지만, 표 데이터에서는 **어떤 열을 이웃으로 묶을지가 사람이 정하는 임의의 선택**이 됩니다. 이 선택에 따라 결과가 달라지므로, 표 데이터에 `Conv1D`를 쓸 때는 이 점을 꼭 기억해야 합니다.
- 또 하나: 9개를 `(3,3)`으로 접을 수 있는 것은 9 = 3×3이기 때문입니다. 특징이 8개라면 `cannot reshape array of size 40 into shape (3,3)` 같은 `ValueError`가 납니다(합성 5행으로 확인). 30개는 `(10,3)`도 `(3,10)`도 가능하지만, **접는 모양에 따라 이웃이 완전히 달라집니다.**

## 4. 시점이 1개가 되면 `GAP`는 `Flatten`과 같다

```python
model.add(Conv1D(16, (3,), input_shape=(3,3)))     # (3,3) -> (1,16)
model.add(Conv1D(32, (2,), padding='same'))        # (1,16) -> (1,32)   ← same이라 길이 유지
model.add(Conv1D(62, (2,), padding='same'))        # (1,32) -> (1,62)
model.add(GlobalAveragePooling1D())                # (1,62) -> (62,)
```

- 커널 3이 시점 3개를 한 번에 보므로 첫 층에서 이미 시점이 1개로 줄어듭니다(`3-3+1=1`).
- 이후 `padding='same'`을 줬기 때문에 시점은 계속 1개입니다.
- `GlobalAveragePooling1D`는 "시점 방향 평균"인데, 시점이 1개면 **평균 낼 것이 하나뿐**이라 값이 그대로 남습니다. 실제로 두 층의 출력을 비교해 보니 완전히 같았습니다(`np.allclose → True`).
- 즉 이 모델에서 `GAP`는 `Flatten`과 똑같이 동작합니다. "GAP를 썼으니 시간 정보를 압축했다"는 효과는 여기서는 없습니다.

실제 파라미터(실행 확인):

| 층 | 출력 모양 | 파라미터 |
|---|---|---|
| `Conv1D(16, (3,))` | `(None, 1, 16)` | `(3×3+1)×16 = 160` |
| `Conv1D(32, (2,), same)` | `(None, 1, 32)` | `(2×16+1)×32 = 1,056` |
| `Conv1D(62, (2,), same)` | `(None, 1, 62)` | `(2×32+1)×62 = 4,030` |
| `GlobalAveragePooling1D()` | `(None, 62)` | 0 |
| `Dense(5, relu)` | `(None, 5)` | `62×5+5 = 315` |
| `Dense(1)` | `(None, 1)` | `5×1+1 = 6` |
| **합계** | | **5,567** |

## 5. `keras68_Conv1D_06_cancer.py` — 30개 특징을 `(10, 3)`으로

```python
x_train = x_train.reshape(-1, 10, 3)   # (398, 30) -> (398, 10, 3)
model.add(Conv1D(36, (2,), input_shape=(10, 3)))
model.add(Conv1D(48, (2,)))
model.add(GlobalAveragePooling1D())
model.add(Dense(30, activation='relu'))
model.add(Dense(15, activation='relu'))
model.add(Dense(1, activation='sigmoid'))
```

| 층 | 출력 모양 | 파라미터 |
|---|---|---|
| `Conv1D(36, (2,))` | `(None, 9, 36)` | `(2×3+1)×36 = 252` |
| `Conv1D(48, (2,))` | `(None, 8, 48)` | `(2×36+1)×48 = 3,504` |
| `GlobalAveragePooling1D()` | `(None, 48)` | 0 |
| `Dense(30, relu)` | `(None, 30)` | `48×30+30 = 1,470` |
| `Dense(15, relu)` | `(None, 15)` | `30×15+15 = 465` |
| `Dense(1, sigmoid)` | `(None, 1)` | `15×1+1 = 16` |
| **합계** | | **5,707** |

- 여기서는 `activation='relu'`가 있어서 2번 파일과 다릅니다. 층 사이에 꺾임이 생기므로 단순 선형 회귀와는 다른 계산을 할 수 있습니다.
- `train_test_split(..., stratify=y)`는 "0과 1의 비율을 훈련/테스트에 똑같이 맞춰라"는 뜻입니다. 실제로 확인하니 훈련 양성 비율 0.628, 테스트 0.626으로 거의 같았습니다. 이 옵션이 없으면 한쪽에 양성이 몰려 정확도가 들쭉날쭉해질 수 있습니다.
- 30에폭만 학습한 소규모 재현에서 `loss 0.3225`, `acc 0.8596`이 나왔습니다. 주석의 `acc 0.9415`는 10,000에폭 설정의 원본 기록이며 이번에 재현하지는 않았습니다.

## 6. `MinMaxScaler`는 훈련 데이터로만 `fit`

```python
scaler = MinMaxScaler()
scaler.fit(x_train)          # 기준(최솟값·최댓값)은 훈련 데이터에서만
x_train = scaler.transform(x_train)
x_test  = scaler.transform(x_test)
```

- `fit`은 "이 데이터의 최솟값을 0, 최댓값을 1로 만들겠다"는 **기준을 정하는** 일입니다.
- 테스트 데이터로도 `fit`을 하면, 시험 문제의 답을 미리 보고 기준을 정하는 셈입니다(정보 누출, data leakage).
- 그래서 테스트 값은 `0~1`을 벗어날 수 있습니다. 실제 확인 결과:

| 구분 | 최솟값 | 최댓값 |
|---|---|---|
| 훈련 (변환 후) | 0.0 | 1.0 |
| 테스트 (변환 후) | -0.0913 | 1.2725 |

- 테스트 1,100칸 중 **6칸**이 `0~1` 밖으로 나갔습니다. 파일 주석의 `-0.09132350124497224`, `1.2724968314321925`와 정확히 같은 값입니다. 즉 이 주석은 맞습니다.
- `0~1`을 살짝 벗어나는 것은 신경망에 치명적이지 않습니다. 하지만 많이 벗어나면(`StandardScaler`나 `RobustScaler`를 쓰는 이유) 학습이 불안정해질 수 있습니다.

## 7. `z_evaluate.py`가 분류에도 `r2`·`mse`를 찍는 이유

`keras2/z_evaluate.py`(15줄)는 이렇게 생겼습니다.

```python
def evaluate(model, x_test, y_test, start_time, end_time, *, name=None):
    loss = model.evaluate(x_test, y_test)
    y_predict = model.predict(x_test)
    r2 = r2_score(y_test, y_predict)
    mse = mean_squared_error(y_test, y_predict)
    print(...)   # loss[0], round(loss[1],4), r2, mse
```

- 회귀용으로 만든 함수인데 분류 파일(`keras68_Conv1D_06_cancer.py`)에서도 그대로 불러 씁니다. 그래서 `r2 : 0.4597`, `mse : 0.1265`가 찍힙니다.
- **문제 1**: `y_predict`를 반올림하지 않고 그대로 씁니다. 즉 0.83, 0.12 같은 **확률값**에 `r2`·`mse`를 계산합니다. 정답이 0/1인데 예측이 확률이면 이 점수는 "분류를 얼마나 잘했나"를 뜻하지 않습니다.
- **문제 2**: 반올림한 예측으로 `mse`를 구하면 재미있는 관계가 생깁니다. 정답이 0/1이므로 틀린 칸만 `(1-0)²=1` 또는 `(0-1)²=1`이 되어, `mse = 틀린 개수 / 전체 = 1 - 정확도`가 됩니다. 실제로 확인했습니다: `mse(반올림) = 0.1287`, `1 - acc = 0.1287`로 정확히 같았습니다.
- 정리: 분류에서는 **정확도(accuracy)** 를 봐야 하고, `r2`·`mse`는 확률값에 대한 참고용 숫자일 뿐입니다. 반올림 전후로도 `mse`가 `0.0939 → 0.1287`, `r2`가 `0.5988 → 0.4506`으로 크게 달라집니다.

## 8. `keras68_Conv1D_04`에서 제출 파일을 만들 수 없는 이유

이 파일은 `test.csv`(715행)와 `submission.csv`를 읽어 오지만, 그 뒤에 **제출 파일을 만드는 코드가 없습니다.**

- `test_csv`를 `scaler.transform` 하는 코드가 없습니다(학습은 스케일된 값으로 했으므로 예측도 스케일해야 함).
- `test_csv`를 `(샘플, 3, 3)`으로 `reshape` 하는 코드가 없습니다.
- `test_csv`에 `model.predict`를 하는 코드가 없고, `submission_csv`에 값을 넣어 `to_csv`로 저장하는 코드도 없습니다.
- 실제로 파일 안에서 `test_csv`가 등장하는 곳은 읽기, `info()`, `fillna` 뿐이고, `predict`는 `x_test`(훈련에서 떼어 낸 검증용)에만 쓰입니다.

즉 이 파일은 "모델 성능(r2 0.5980) 확인"까지만 하는 상태입니다. 제출용으로 만들려면 `test_csv` 결측치 처리 → 스케일 변환 → `reshape(-1,3,3)` → `predict` → `submission_csv`에 채우기 → `to_csv` 순서가 필요합니다.

또 하나: `root_mean_squared_error`는 scikit-learn 1.4부터 제공되는 함수입니다. 이 환경(1.4.2)에서는 정상 import 되었지만, 그보다 오래된 버전에서는 `ImportError`가 납니다.

## 9. 코드·주석에서 실제와 다른 점

1. `keras68_Conv1D_02_diabetes.py` — `Conv1D`·`Dense`에 `activation`이 전혀 없어 6층 모델이 사실상 선형 회귀가 됩니다(실측 `r2` 0.4165 vs 선형 회귀 0.4190). 주석의 `r2 0.408`은 이 구조의 한계를 보여 줍니다.
2. `keras68_Conv1D_02_diabetes.py` — `patience=1500`에 `epochs=10000`이라 조기 종료가 사실상 거의 걸리지 않습니다. 10-27에서 배운 대로 `patience`는 보통 10~50 수준입니다.
3. `keras68_Conv1D_04_dacon_ddarung.py` — 제출 코드(`test_csv` 스케일·reshape·predict·`to_csv`)가 없습니다. `submission_csv`를 읽어만 놓고 쓰지 않습니다.
4. `keras68_Conv1D_04_dacon_ddarung.py` — `test_csv`는 평균으로 결측치를 채우고 `train_csv`는 `dropna()`로 지웁니다. 학습/예측 처리가 서로 다르므로, 실제 제출 시에는 두 처리 중 하나로 통일하는 편이 좋습니다.
5. `keras68_Conv1D_06_cancer.py` — 맨 아래 주석의 `r2`, `mse`, `rmse2`는 이 파일이 계산한 값이 아니라 `z_evaluate.py`가 회귀용 지표를 그대로 찍은 것입니다. 분류 성능은 `acc`로 봐야 합니다.
6. `keras68_Conv1D_06_cancer.py` — `root_mean_squared_error`와 `MinMaxScaler`·`StandardScaler`·`MaxAbsScaler`를 import 했지만 실제로는 쓰지 않습니다(주석 처리된 코드에만 등장). 실행에는 지장이 없지만, 이 파일이 어떤 지표를 보는지 헷갈리게 만듭니다.
7. 세 파일 공통 — 표 데이터에 `Conv1D`를 쓰면서 "시점"의 의미를 정하지 않았습니다. 열 순서를 바꾸면 결과가 달라지는 것(실측 `[70,133]` vs `[62,125]`)을 확인했으므로, 이 구조는 성능 실험이지 원리 설명용으로만 보는 것이 안전합니다.

## 반드시 기억할 점

- `Conv1D` 파라미터는 `(커널 × 입력채널 + 1) × 필터` — 시점 개수와 무관.
- 출력 시점 길이는 `입력 - 커널 + 1` (`padding='same'`이면 유지).
- 시점이 1개면 `GlobalAveragePooling1D`와 `Flatten` 결과는 같다.
- 활성화 함수가 없으면 층을 아무리 쌓아도 결국 선형 계산 하나다.
- 스케일 기준(`fit`)은 훈련 데이터로만 잡는다. 테스트가 `0~1`을 벗어나는 것은 정상이다.
- 분류에서는 `r2`·`mse`보다 `acc`를 본다. 반올림 예측의 `mse`는 `1 - 정확도`와 같다.
- 제출 파일은 "스케일 → reshape → predict → to_csv" 네 단계가 모두 있어야 만들어진다.
