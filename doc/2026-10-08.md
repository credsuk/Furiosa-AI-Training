## 오늘 배운 내용 — 초보자용 설명

오늘 코드는 크게 두 가지입니다. 첫째, PDF 문서를 읽고 검색 가능한 숫자 벡터로 바꾸어 RAG 챗봇을 만드는 흐름입니다. 둘째, 서로 다른 입력 묶음을 각각 작은 신경망에 넣은 뒤 결과를 이어 붙여 하나의 예측을 만드는 앙상블 모델입니다.

### 1. RAG 흐름

`RAG/reg19_PyPDF.py`의 `PyPDFLoader`는 PDF를 페이지별 문서 목록으로 읽습니다. 문서를 잘게 나누고 임베딩 모델로 숫자 벡터를 만든 다음, `FAISS.from_documents()`로 벡터 저장소를 만들고 저장합니다. 이후 `FAISS.load_local()`로 저장소를 불러오면 질문과 가까운 문서를 검색할 수 있습니다.

`RAG/reg20_embedding2_bge-m3.py`와 `reg20_embedding3_qwen3.py`는 문장을 임베딩해 벡터 길이를 확인합니다. BGE-M3와 Qwen 모델의 실제 실행 결과는 이 작업에서 다시 실행하지 않았으므로, 코드 주석의 차원 수를 실제 결과로 단정하지 않습니다.

`RAG/rag19_PyPDF_2_챗봇.py`와 `reg20_embedding4_챗봇.py`의 흐름은 `질문 → retriever가 관련 문서 검색 → prompt에 context 삽입 → LLM 답변 → Gradio 화면`입니다. `k=3` 또는 `k=2`는 검색할 문서 조각 수입니다. `allow_dangerous_deserialization=True`는 pickle 역직렬화를 허용하므로 신뢰하는 파일에서만 사용해야 합니다.

### 2. 다중 입력 앙상블

`keras2/keras69_ensemble1.py`은 shape `(100, 2)`인 `x1`과 `(100, 3)`인 `x2`를 각각 입력으로 사용합니다. `train_test_split`에 여러 배열과 `y`를 함께 넣으면 같은 순서로 나뉘므로 샘플 대응 관계가 유지됩니다. 첫 번째 가지의 출력 shape는 `(batch, 80)`, 두 번째 가지의 출력 shape는 `(batch, 40)`이고, `Concatenate` 후에는 `(batch, 120)`이 됩니다. 그 뒤 Dense 층을 지나 최종 출력은 `(batch, 1)`입니다.

`keras69_ensemble2.py`은 세 번째 입력 `(100, 4)`를 추가하여 세 가지 정보를 합칩니다. `keras69_ensemble3.py`은 마지막을 두 갈래로 나누어 `y1`, `y2`를 동시에 예측합니다. 이때 모델의 출력 목록과 `fit()`에 전달하는 정답 목록의 순서가 서로 맞아야 합니다. 중간에 만든 `last_dense1`, `last_dense2`는 실제 출력에 연결되지 않아 현재 예측에는 사용되지 않습니다.

## 반드시 기억할 점

1. RAG는 문서를 읽고, 나누고, 임베딩하고, 저장하고, 질문과 가까운 조각을 검색한 뒤 답변에 참고시키는 순서입니다.
2. `Embedding` 벡터는 의미를 숫자 배열로 표현한 것이며, FAISS는 이 벡터들의 가까운 정도를 빠르게 찾는 저장소입니다.
3. `Concatenate`는 같은 batch 축을 유지하면서 마지막 feature 축을 이어 붙입니다. `(batch, 80)`과 `(batch, 40)`은 `(batch, 120)`이 됩니다.
4. 다중 입력에서는 각 입력의 첫 번째 축 샘플 순서가 같아야 합니다.
5. 다중 출력에서는 `outputs=[out1, out2]`와 `fit(..., [y1, y2])`의 순서가 일치해야 합니다.
6. `input_dim`/입력 shape와 실제 데이터 shape를 코드로 확인해야 하며, 주석에 적힌 실행 결과만 믿으면 안 됩니다.
7. `allow_dangerous_deserialization=True`는 편리하지만 출처를 신뢰할 수 없는 pickle 파일에 사용하면 위험합니다.
8. `DB_PAHT`는 오타처럼 보이지만 같은 이름을 일관되게 사용하면 실행 자체는 가능할 수 있습니다. 다만 `PATH`로 고치는 등 명확한 이름을 쓰는 편이 안전합니다.

## Python·NumPy·pandas 연결

- Python: `def answer_invoke(message, history)`처럼 함수는 입력을 받고 결과를 `return`해야 바깥 코드가 사용할 수 있습니다. 사용하지 않는 `history`도 함수 시그니처와 라이브러리의 호출 규약 때문에 받을 수 있습니다.
- NumPy: `np.array([...]).T`는 행으로 만든 데이터를 전치해 `(샘플, feature)` 모양으로 바꿉니다. `x1`은 `(100, 2)`, `x2`는 `(100, 3)`이므로 한 샘플의 입력 feature 수가 다릅니다.
- pandas: 실제 CSV를 DataFrame으로 읽는 경우에도 입력 열을 `X`, 정답 열을 `y`로 나누고, 여러 입력 묶음을 합칠 때 행 순서와 인덱스가 같은지 확인해야 합니다. 오늘 저장소의 신규 코드는 pandas를 직접 사용하지 않았으므로 DataFrame 실행 결과는 확인하지 않았습니다.
