## 코드 흐름: 입력 → 처리 → 출력

```text
원본 배열/CSV
  → window 생성(split_x)
  → X는 과거 timestep, y는 다음 timestep/feature
  → (샘플, timestep, feature) shape로 정리
  → 필요하면 train/test 시간 순서 분할
  → train 데이터 기준 MinMaxScaler 적용
  → LSTM/GRU → Dense
  → loss 평가와 다음 구간 예측
```

### 작은 시계열 예제

`keras56_split3.py`의 `a = np.array(range(1, 101))`, `size=6`에서는 window가 `(95, 6)`이고, `bbb[:, :-1]`을 X로 사용하면 `(95, 5)`, `bbb[:, -1:]`을 y로 사용하면 `(95, 1)`이 됩니다. 다만 모델 입력은 `input_shape=(5, 1)`이므로 실제 실행 전에는 X를 `(95, 5, 1)`로 맞추는지 확인해야 합니다. 파일의 주석 출력 `(94, 5)`, `(94, 1)`은 현재 코드의 `range(len(dataset) - size + 1)` 결과 `(95, 6)`과 일치하지 않아 재검증이 필요합니다.

`keras56_split4.py`는 먼저 `a.reshape(-1, 2)`로 `(50, 2)`를 만들고, 6행 window를 만들면 `(45, 6, 2)`, `x = bbb[:, :-1, :]`는 `(45, 5, 2)`, `y = bbb[:, -1:, 1]`은 `(45, 1)`입니다. 입력은 `input_shape=(5, 2)`입니다.

`keras56_split2.py`의 다중 feature 예제는 `(10, 2)` 배열을 5 timestep window로 나누어 `(6, 5, 2)`가 되는 구조이며, 함수 버전에서는 timestep 4에 대해 X `(5, 4, 2)`, y 원본 `(5, 1, 2)`를 만든 뒤 `y[:, 0, 1]`로 두 번째 feature만 골라 `(5,)`로 줄입니다.

### return_sequences 비교

- `keras57_01_return_sequence.py`: LSTM과 GRU 여러 층이 이어지므로 중간 recurrent 층은 `return_sequences=True`로 전체 시퀀스 `(batch, timestep, units)`를 다음 층에 전달하고, 마지막 LSTM은 기본값으로 마지막 상태만 출력합니다.
- `keras57_02_return_sequence.py`: LSTM·GRU 출력 전체를 `Flatten()`으로 펴서 Dense 층에 전달합니다. `return_sequences=True`는 성능 향상 스위치가 아니라 다음 층에 timestep 전체가 필요한지 결정하는 shape 옵션입니다.

### Bidirectional과 RAG 흐름

- `keras59_Bidirectional1.py`는 입력 `(7, 3)`을 `(7, 3, 1)`로 reshape한 뒤 `Bidirectional(SimpleRNN(16))`에 전달합니다. 기본 `merge_mode='concat'`이고 마지막 timestep 출력만 반환하는 설정이면 방향별 16 units를 합쳐 출력 feature가 32가 됩니다. `Bidirectional`은 recurrent layer를 감싸는 wrapper이지 독립적인 전체 모델이 아닙니다.
- `keras59_Bidirectional3_jena.py`는 `T (degC)`를 target으로 바꾸고 `Bidirectional(LSTM(36, return_sequences=True)) → GRU(48) → Dense(144)` 흐름을 구성합니다. 입력 window는 144 timestep × 13 feature입니다.
- 양방향 처리는 각 입력 window 안에서 앞·뒤 방향 문맥을 읽습니다. 예측 시점 이후의 값을 입력 window에 넣으면 누수지만, 예측 시점까지 관측된 window 내부를 역방향으로 처리하는 것만으로 곧바로 누수라고 단정할 수는 없습니다.

```text
질문 → PromptTemplate → ChatOpenAI → (선택) StrOutputParser → 문자열 답변
```

- `RAG/_llm.py`는 `getOpenAi()`, `setPrompt(str=..., template=...)`, `invoke(prompt, input, parser=None)`, `getParser()`를 제공하도록 작성되어 있습니다. `invoke`는 LCEL의 `prompt | model | parser` 체인을 호출합니다.
- `PromptTemplate.from_template(...)`은 `{topic}` 같은 입력 변수를 가진 프롬프트를 만들고, 체인의 `invoke`에 해당 키를 가진 dictionary를 전달합니다. `StrOutputParser`를 포함하면 모델 출력을 문자열로 파싱합니다.
- `RAG/rag08_LCEL02.py`는 helper에 정의되지 않은 `setPromptTemplate`을 호출하지만 helper의 실제 이름은 `setPrompt`입니다. 이 이름을 그대로 실행하면 `AttributeError`가 날 가능성이 있어 실행 전 수정·검증이 필요합니다.
- RAG의 개념은 검색 → 검색 문맥 추가 → 생성입니다. Embedding/vector store 관련 내용은 날짜별 학습 메모의 개념 연결이며 day20 코드에서 실제 vector database를 구성한 것은 아닙니다.

### Jena 기후 데이터

`keras/keras58_kaggle_jena1.py`의 day19 버전은 `wd (deg)`를 target으로 사용했고, day20 commit에서는 target이 `T (degC)`로 바뀌었습니다. day20 코드는 `x_data`에서 `T (degC)`를 제거하지만 `x_predict`에서는 `wd (deg)`를 제거합니다. 따라서 학습 입력 feature와 예측 입력 feature의 구성·순서가 달라질 위험이 있습니다. 이는 소스에서 확인한 잠재 결함이며 여기서 모델 실행은 하지 않았습니다.

10분 간격 데이터의 하루는 144 timestep입니다. 144-window 입력은 `(420120, 144, 13)`, target window는 `(420120, 144)`로 코드 주석에 기록되어 있습니다. `train_test_split(..., shuffle=False)`로 시간 순서를 유지하고, scaler는 train에만 `fit`한 뒤 test에 `transform`합니다. 최종 Dense 출력은 144개입니다.

## 반드시 기억할 내용

1. 시계열 입력은 `(batch, timestep, feature)`이고 `input_shape`에는 batch를 넣지 않습니다.
2. `bbb[:, :-1]`은 마지막 timestep을 제외하고, `bbb[:, -1:]`은 마지막 timestep을 2차원 축으로 유지합니다. `-1`은 해당 축을 제거할 수 있습니다.
3. 시간 순서를 보존해야 하는 평가에서는 `shuffle=False`를 명시하고, scaler도 train 데이터로만 fit합니다.
4. `validation_split=0.01`은 작은 데이터에서 검증 샘플이 지나치게 적을 수 있습니다.
5. 모델 전체 데이터를 `evaluate(x, y)`에 넣은 결과는 학습 데이터 성능이며 일반화 성능의 증거가 아닙니다.

## 헷갈리기 쉬운 부분과 흔한 오류

- `size=6`인 1차원 window는 입력 6개가 아니라, 마지막 하나를 target으로 떼면 입력 timestep 5개입니다.
- `y[:, 0, 1]`은 “첫 timestep·두 번째 feature” 선택이며, 모든 샘플에 대해 결과 shape가 `(샘플,)`이 됩니다.
- `reshape(-1, 5, 2)`는 전체 원소 수가 5×2로 나누어져야 합니다. 예측 배열 10개라면 `(1, 5, 2)`입니다.
- Jena 데이터에서 `datasets[-144:]`는 마지막 144행을 선택하지만, 날짜 열을 `index_col=0`으로 읽었다는 전제와 실제 CSV 형식을 확인해야 합니다.
- `keras56_split3.py`의 출력 주석과 계산 가능한 window 수가 다릅니다. 실행 검증 없이 주석 결과를 사실로 사용하지 않습니다.

## 학습 보강: Python·NumPy·pandas

### Python 문법

```python
def split_x(dataset, size):
    windows = []
    for i in range(len(dataset) - size + 1):
        subset = dataset[i:i + size]
        windows.append(subset)
    return np.array(windows)
```

`def`는 함수를 정의하고, `for`는 시작 위치를 순회하며, `dataset[i:i + size]`는 끝 인덱스 직전까지 잘라 새 window를 만듭니다. `return`은 리스트를 NumPy 배열로 바꾼 값을 호출자에게 돌려줍니다. `range(len(dataset) - size + 1)`의 `+1`은 마지막 가능한 window를 포함합니다.

### NumPy

```python
arr = np.arange(1, 11).reshape(5, 2)
# shape: (5, 2)
windows = np.array([arr[i:i+3] for i in range(3)])
# shape: (3, 3, 2)
x = windows[:, :-1, :]
y = windows[:, -1:, 1]
# x: (3, 2, 2), y: (3, 1)
```

`reshape`는 원소 수를 바꾸지 않고 축을 재배열합니다. `axis=0`은 첫 축에 새 차원을 넣는 `np.expand_dims`에서 배치 축을 추가할 때 쓰입니다. `concat`/`stack`/`split`은 이번 day19 파일의 핵심 실행에는 직접 등장하지 않았으므로 실제 사용을 확인하지 않은 설명은 추가하지 않습니다.

### pandas

```python
datasets = pd.read_csv(path + 'jena_climate_2009_2016.csv', index_col=0)
x_data = datasets[:-288].drop(['wd (deg)'], axis=1).to_numpy(dtype=np.float32)
y_data = datasets[144:-144]['wd (deg)'].to_numpy(dtype=np.float32)
```

`read_csv`는 DataFrame을 반환하고, `drop(..., axis=1)`은 열을 제거하며, 열 하나를 선택한 결과는 Series입니다. `to_numpy(dtype=...)`는 NumPy 배열로 변환하면서 dtype을 지정합니다. `head()`, `info()`, `describe()`, `loc`, `iloc`, `merge`, `groupby`, 결측치 처리는 오늘 코드에서 직접 실행한 근거가 없어 확인 불가로 둡니다.

### 학습 주제 연결: CNN·양방향 RNN·RAG

아래 내용은 저장소의 day19 코드 실행으로 확인한 동작이 아니라 날짜별 학습 메모에서 나온 질문·연결 주제입니다.

- CNN은 항상 여러 층이어야 하는 것은 아닙니다. 합성곱 층을 쌓으면 여러 수준의 특징을 학습할 수 있지만, 층 수는 문제·데이터·모델 설계에 따라 달라집니다.
- RNN/LSTM/GRU도 여러 층으로 연결할 수 있습니다. 중간 recurrent 층이 timestep 전체 출력을 다음 층에 전달해야 할 때 `return_sequences=True`를 사용합니다. 층을 많이 쌓는다고 성능이 자동으로 좋아지지는 않습니다.
- Bidirectional recurrent layer는 입력 시퀀스를 순방향과 역방향으로 처리해 양쪽 문맥을 결합합니다. 다만 미래 시점 정보를 사용하므로, 예측 시점 이후 정보를 써서는 안 되는 실시간·인과 예측 문제에는 적용 가능성을 따져야 합니다.
- RAG는 Retrieval → Augmented → Generation의 흐름입니다: 질문과 관련된 외부 자료를 검색하고, 검색 결과를 입력 문맥에 보강한 다음, 그 근거를 바탕으로 답변을 생성합니다. 모델을 매번 재학습하지 않고 검색 시점에 지식을 제공할 수 있지만, 검색 품질과 문맥 구성에 따라 답변 품질이 달라집니다.
- Embedding은 텍스트 등을 벡터로 표현하는 방법이고, vector store/DB는 벡터와 관련 문서 정보를 저장해 유사 항목 검색에 활용합니다. LangChain은 LLM 애플리케이션 구성 프레임워크이며 LCEL은 runnable 구성 요소를 연결하는 표현 방식으로 이해합니다. 이는 학습 메모의 개념 설명이며 day19 저장소 코드에서 실행된 사실은 아닙니다.
