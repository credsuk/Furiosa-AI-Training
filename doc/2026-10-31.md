- `reset_index(drop=True)`는 남은 줄의 번호를 **0, 1, 2, …로 다시 매기고, 원래 번호표(인덱스)는 버린다**는 뜻입니다. 중간이 잘려 나갔으니 번호가 0,3,7,… 처럼 띄엄띄엄 남기 때문입니다.

**실측으로 확인한 성질 (합성 데이터 10줄):**

- `isin`으로 거른 결과는 **원본 파일의 줄 순서를 그대로 유지**합니다. 최신순으로 저장된 파일을 정렬하지 않고 `isin`만 쓰면, 결과도 여전히 최신순입니다. 즉 `sort_values`를 **먼저** 해야 날짜가 옛날 → 오늘 순서가 됩니다.
- 같은 날짜가 두 번 들어 있는 파일이면 `isin`은 **두 줄을 다 남깁니다.** 10줄짜리 파일에 1줄을 복제해 넣었더니 결과가 11줄이 되어, 삼성전자(10줄)와 길이가 어긋났습니다. 이러면 창을 잘라도 샘플 수가 서로 달라져 학습할 때 모양 오류가 납니다.

## 2. 창 20일로 자르고, 정답을 붙인다 — 여기에 큰 함정이 있다

```python
def split_xy(dataset, size):
    aaa = []
    for i in range(len(dataset) - size + 1):
        aaa.append(dataset[i : (i+size)])
    return np.array(aaa)

split_size = 20
x1_windowed = split_xy(x1_filtered, split_size)   # (창 개수, 20, 6)
x2_windowed = split_xy(x2_filtered, split_size)   # (창 개수, 20, 6)
x3_windowed = split_xy(x3_filtered, split_size)   # (창 개수, 20, 5)
y_windowed  = y_data[split_size - 1 :]            # 시가 전체에서 앞 19개를 버림
```

**모양 계산 (실측):** 줄이 1120개면 창은 `1120 - 20 + 1 = 1101`개이고, 정답도 `1101`개입니다. `int(1101 × 0.8) = 880`이라 훈련 880창, 시험 221창이 됩니다(880 + 221 = 1101). 파일에 적힌 주석 `(880, 20, 6)`·`(221, 20, 6)`과 정확히 맞습니다.

**함정:** `y_windowed = y_data[19:]`의 i번째 값은 **i번째 창의 마지막 날 시가**입니다.

- 0번 창 = 0~19번째 줄. 정답 = 19번째 줄(창의 마지막 날)의 시가.
- 그런데 그 창 안에는 **19번째 줄의 종가**도 들어 있습니다(삼성전자 갈래의 `종가` 열).
- 하루의 순서는 `시가 → … → 종가`입니다. 즉 모델은 **그날 장이 끝난 뒤의 값(종가)을 보고 그날 아침 값(시가)을 맞히는** 셈입니다. 이건 "다음 날을 맞히는 문제"가 아니라 **"이미 지나간 하루를 거꾸로 맞히는 문제"** 입니다. 시험 점수는 좋게 나오지만 실제로 내일 주가를 맞히는 능력과는 관계가 없습니다.

합성 데이터(시가 = 종가 − 100인 결정적 관계)로 확인한 결과입니다. 창의 마지막 종가 하나만 가지고 선형 모델로 맞혀 봤습니다.

| 정답을 무엇으로 잡았나 | 오차(RMSE) | 기울기 | 참고: "전날 종가를 그대로 쓴다"의 오차 |
|---|---|---|---|
| 코드 그대로: **같은 날 시가** | **0.00** | 1.0000 | 100.00 |
| 올바른 정답: **다음 날 시가** | 197.04 | 0.9595 | 222.26 |

- 코드 그대로면 창의 마지막 종가만으로 정답을 **완벽하게** 계산할 수 있습니다(오차 0). 정보가 이미 새어 들어왔다는 뜻입니다.
- 다음 날 시가는 갭(밤사이 변동) 때문에 잘 맞지 않습니다. 단순히 "전날 종가를 그대로 쓰기"(222.26)보다 조금 나은 정도(197.04)입니다.
- 참고로 이때 가격 **레벨** 기준 R²는 0.92로 "잘 맞는 것처럼" 보입니다. 가격은 크기가 크고 완만히 움직여서 R²가 원래 커 보입니다. 그래서 주가 문제에서는 R² 하나만 보면 안 됩니다.

**고치는 방법(개념):** 정답은 창 **다음** 날이어야 합니다.

```python
y_windowed = y_data[split_size:]      # 창 i의 다음 날 시가 -> 길이가 창 개수보다 1개 적다
x1_windowed = x1_windowed[:-1]        # 그래서 마지막 창은 짝이 없으니 버린다
```

## 3. 3차원을 펴서 스케일링하고, 다시 접는다

```python
def minMax_split(train_data, test_data):
    train_2d = train_data.reshape(-1, train_data.shape[-1])   # (880, 20, 6) -> (17600, 6)
    test_2d  = test_data.reshape(-1, test_data.shape[-1])     # (221, 20, 6) -> (4420, 6)
    scaler = MinMaxScaler()
    scaler.fit(train_2d)                 # 훈련 데이터로만 fit
    train_scaled = scaler.transform(train_2d)
    test_scaled  = scaler.transform(test_2d)
    return train_scaled.reshape(train_data.shape), test_scaled.reshape(test_data.shape), scaler
```

- `MinMaxScaler`는 **2차원 표**만 받습니다. 그래서 `(샘플, 날짜, 특징)`을 `(샘플×날짜, 특징)`으로 펴서 "특징 6개씩 묶인 줄이 17,600개"로 만듭니다. 스케일링이 끝나면 `reshape(train_data.shape)`로 **원래 3차원 모양으로 되돌립니다.**
- `fit`은 "각 특징의 최솟값·최댓값을 재는 일", `transform`은 "그 기준으로 0~1 사이 값으로 바꾸는 일"입니다. `fit`을 **훈련 데이터로만** 하는 이유는, 시험 데이터의 최댓값을 미리 알면 그건 미래 정보를 쓰는 것이기 때문입니다.
- 대신 **시험 데이터가 0~1을 벗어날 수 있습니다.** 상승 추세인 합성 데이터(훈련 80줄, 시험 20줄)로 확인했더니 시험 값의 60개 중 **57개가 1을 넘었고 최댓값이 1.2104**였습니다. 훈련 때 본 적 없는 범위이므로 모델이 그 구간을 잘 다루지 못합니다.
- 참고: `(880, 20, 6)`을 `reshape(-1, 6)` 하면 `880 × 20 = 17,600`줄이 됩니다. 창이 겹치기 때문에 **같은 날짜 줄이 여러 번 들어갑니다**(하루가 최대 20개 창에 등장). 최솟값·최댓값만 재는 `MinMaxScaler`에서는 결과가 달라지지 않지만, 평균·표준편차를 쓰는 `StandardScaler`에서는 값이 조금 달라집니다.

정답(가격)도 숫자가 커서 따로 스케일링합니다.

```python
y_scaler = MinMaxScaler()
y_train = y_scaler.fit_transform(y_train.reshape(-1, 1))   # (880,) -> (880, 1)
y_test  = y_scaler.transform(y_test.reshape(-1, 1))
...
pred_price = y_scaler.inverse_transform(pred_scaled)       # 0~1 값을 다시 '원' 단위로
```

`inverse_transform`은 `transform`의 정확한 반대 계산입니다. 실측으로 `inverse_transform(transform(x))`가 원래 값과 **완전히 같아지는 것**(`np.allclose` True)을 확인했습니다.

## 4. 세 갈래를 만들어 잇는다

| 갈래 | 입력 | 중간 | 갈래 출력 |
|---|---|---|---|
| ① 아모레 | `(None, 20, 6)` | LSTM 20(시퀀스 유지) → LSTM 128(유지) → LSTM 64 | `(None, 10)` |
| ② 하이닉스 | `(None, 20, 6)` | LSTM 63(유지) → LSTM 128(유지) → LSTM 36 | `(None, 10)` |
| ③ 삼성전자 | `(None, 20, 5)` | Conv1D 8(커널3, same) → Conv1D 32(커널3, same) → Conv1D 64(커널1) → Conv1D 16(커널1) → Flatten(320) → Dense 30 | `(None, 20)` |

```python
merge1 = Concatenate()([output1, output21, output31])   # (None, 10+10+20) = (None, 40)
merge2 = Dense(70, activation='relu')(merge1)
merge3 = Dense(5, activation='relu')(merge2)
last_output = Dense(1, name='final_output')(merge3)      # 가격 1개
model = Model(inputs=[input1, input21, input31], outputs=last_output)
```

- `Concatenate`는 **이어 붙이기**만 합니다. 더하기·평균이 아닙니다. 길이 10·10·20을 붙이면 40이 됩니다.
- 갈래마다 출력 길이를 10·10·20으로 맞춰 둔 것은 "각 회사 정보를 같은 크기의 요약으로 만든 뒤 붙이겠다"는 뜻입니다. 숫자 10/20/63/36에는 계산 근거가 없고 사람이 고른 값입니다.
- `padding='same'`은 "합성곱을 해도 날짜 수 20을 그대로 유지"합니다. `padding`을 적지 않으면 커널 3에서 20 → 18 → 16으로 줄어듭니다.
- `Conv1D(64, 1)`처럼 **커널 크기 1**은 날짜를 넘나들지 않고 **그 날짜 하나 안에서만** 계산합니다. 파라미터 수도 `(1×32+1)×64 = 2,112`로, 같은 32→64 `Dense`(33×64 = 2,112)와 똑같습니다. 즉 "날짜마다 따로 적용되는 Dense"입니다.

## 5. 파라미터 계산 (실측 총 298,761개)

LSTM 공식은 `4 × ((입력 크기 + 유닛) × 유닛 + 유닛)`입니다. 앞의 `4`는 LSTM 안에 있는 **네 개의 문(게이트)** — 잊기·입력·출력·새 기억 후보 — 때문입니다.

|---|---|---|
| LSTM 20 (입력 6) | 4×((6+20)×20+20) | 2,160 |
| LSTM 128 (입력 20) | 4×((20+128)×128+128) | 76,288 |
| LSTM 64 (입력 128) | 4×((128+64)×64+64) | 49,408 |
| LSTM 63 (입력 6) | 4×((6+63)×63+63) | 17,640 |
| LSTM 128 (입력 63) | 4×((63+128)×128+128) | 98,304 |
| LSTM 36 (입력 128) | 4×((128+36)×36+36) | 23,760 |
| Dense 80 (입력 64) | (64+1)×80 | 5,200 |
| Dense 30 (입력 80) | (80+1)×30 | 2,430 |
| Dense 10 (입력 30) | (30+1)×10 | 310 |
| Dense 80 (입력 36) | (36+1)×80 | 2,960 |
| Dense 30 (입력 80) | (80+1)×30 | 2,430 |
| Dense 10 (입력 30) | (30+1)×10 | 310 |

## 6. `validation_split=0.2`는 "뒤쪽 20%"를 쓴다 (실측 확인)

```python
model.fit([x1_train, x2_train, x3_train], y_train,
          epochs=100000, batch_size=42,
          validation_split=0.2,
          callbacks=[es, rlr, mcp])
```

- `validation_split=0.2`는 데이터를 섞지 않고 **뒤에서 20%를 검증용으로 떼어 냅니다**(`shuffle` 기본값 False).
- 확인 방법: 훈련 데이터 100개를 "앞 80개는 0, 뒤 20개는 100"으로 만들고 1에폭 학습시켰더니 `loss 0.0`, `val_loss 10000.0`이 나왔습니다. 검증이 **뒤쪽 20%** 였다면 정답이 전부 100이라 오차가 100² = 10,000이 되고, 무작위로 섞었다면 2,000 근처가 됩니다. 결과는 10,000이므로 뒤쪽 20%가 맞습니다.
- 시계열(주가)에서는 이 동작이 **오히려 맞습니다.** 무작위로 섞으면 미래 날짜가 훈련에, 과거 날짜가 검증에 들어가 "미래를 보고 과거를 맞히는" 평가가 되기 때문입니다. 다만 검증 구간이 시험 구간 바로 앞 20%라, 조기 종료로 고른 모델이 시험 구간에 아주 가까운 구간에서 선택된다는 점은 기억해 둘 만합니다.

## 7. 콜백 3종

```python
mcp = ModelCheckpoint(monitor='val_loss', mode='auto', save_best_only=True,
                      filepath="./_save/keras70/kaggle_70_{epoch:04d}-{val_loss:.4f}.keras", verbose=1)
rlr = ReduceLROnPlateau(monitor='val_loss', mode='min', patience=100, verbose=1, factor=0.1)
es  = EarlyStopping(monitor='val_loss', mode="min", patience=300, restore_best_weights=True)
```

- `ModelCheckpoint`: `val_loss`가 가장 좋을 때만 파일로 저장. 파일 이름에 `{epoch:04d}`(에폭 4자리), `{val_loss:.4f}`(소수 4자리)를 넣어 어느 에폭이 얼마였는지 알 수 있게 합니다. **디스크에 파일을 쓰는 부작용**이 있습니다.
- `ReduceLROnPlateau`: `val_loss`가 `patience=100` 에폭 동안 좋아지지 않으면 학습률에 `factor=0.1`을 곱해 **10분의 1로 줄입니다.**
- `EarlyStopping`: `patience=300` 에폭 동안 좋아지지 않으면 멈추고, `restore_best_weights=True`로 **가장 좋았던 가중치로 되돌립니다.**
- `epochs=100000`은 사실상 "끝까지"라는 뜻이고, 실제로 멈추는 것은 조기 종료입니다. `batch_size=42`에 훈련 880창이면 1에폭에 약 21번 가중치를 고칩니다.

## 8. 마지막 20일로 예측하기

```python
x1_pred = x1_filtered[-20:].to_numpy()                     # (20, 6)
x1_pred = scaler1.transform(x1_pred).reshape(1, 20, 6)     # 스케일 + '샘플 1개' 차원 추가
pred_scaled = model.predict([x1_pred, x2_pred, x3_pred])   # (1, 1) 0~1 값
pred_price = y_scaler.inverse_transform(pred_scaled)       # 원 단위로
print(f'내일 삼성전자 예측 시가: {pred_price[0][0]:,.0f}원')
```

- 모델은 "샘플 여러 개"를 한꺼번에 받습니다. 그래서 창 1개를 넣을 때도 `reshape(1, 20, 6)`으로 **앞에 '샘플 1개' 자리를 만들어** 줍니다. `(20, 6)` 그대로 넣으면 "날짜 20개, 특징 6개짜리 샘플 1개"가 아니라 "특징 6개짜리 샘플 20개"로 해석되어 모양 오류가 납니다.
- `[-20:]`은 "마지막 20줄"입니다. 그런데 이 20줄의 **마지막 날이 정답 날짜와 같은 날**입니다(2절의 함정). 그래서 이 코드가 출력하는 값은 "내일"이 아니라 **"마지막 날의 시가"** 를 흉내 낸 값입니다. 실제로 다음 날을 예측하려면 마지막 20줄의 **다음 날**을 정답으로 두고 학습해야 하고, 예측 입력은 "마지막 20줄"이 맞습니다.
- `y_scaler`를 `transform`이 아니라 `inverse_transform`으로 쓰는 이유: 모델이 내놓는 값은 0~1로 눌린 숫자이므로, 사람이 읽을 수 있는 원 단위로 되돌려야 합니다. `transform`을 또 쓰면 0~1 사이 값이 한 번 더 눌려 엉뚱한 숫자가 됩니다.

## 9. 코드·주석에서 실제와 다른 곳

1. **정답이 미래를 미리 본다(가장 중요).** `y_windowed = y_data[19:]`는 창의 마지막 날 시가를 정답으로 잡습니다. 창에는 그날 종가가 들어 있으므로 시간 순서가 뒤집힙니다. → `y_data[20:]` + 마지막 창 버리기가 올바른 방향입니다.
2. **삼성전자 갈래에서 `시가`를 뺀 이유는 "정답을 직접 주지 않으려고"인데, `종가`는 남겨 두었습니다.** 종가가 시가보다 시간상 뒤이므로, 의도한 것과 반대로 정보가 새는 구조입니다.
3. **주석의 `loss : 0.3237…`, `228,903원`, `훈련 시간 139.4초`는 재현할 수 없습니다.** 원본 CSV가 저장소에 없고, 같은 조건에서 다시 돌려도 가중치 초기값이 달라 값이 달라집니다.
4. **`metrics`를 지정하지 않아 `evaluate`가 loss 하나만 돌려줍니다.** 회귀에서는 정확도 대신 MAE 같은 지표를 함께 보는 편이 좋습니다.
5. **`LSTM(63)`, `LSTM(36)`, 갈래 출력 `10`·`20` 같은 숫자에는 근거가 없습니다.** 실험으로 고른 값이라면 그 이유를 주석에 남기는 편이 좋습니다.
6. **창을 만들 때 `for` 문으로 하나씩 `append`합니다.** 1120줄에서는 문제없지만 데이터가 커지면 느려집니다. (`np.lib.stride_tricks.sliding_window_view`로 한 번에 만들 수 있습니다.)
7. **`ModelCheckpoint`의 `filepath`가 `./_save/keras70/`에 파일을 씁니다.** 폴더가 없으면 저장 단계에서 오류가 납니다.

## 10. 쉬운 비유로 다시 정리

- **날짜 맞추기**는 세 명의 일기장을 "같은 날짜끼리" 옆에 놓는 일입니다. 한 명이 결석한 날은 빼야 합니다.
- **창 자르기**는 20일짜리 창문을 하루씩 밀면서 여는 일입니다. 1120일이면 창문을 1101번 열 수 있습니다.
- **정답 위치**는 "창문이 끝난 **다음** 칸"이어야 합니다. 창문 안의 마지막 칸을 정답으로 쓰면, 창문 안에 이미 들어 있는 답을 보고 맞히는 셈입니다.
- **스케일링**은 서로 다른 단위(원, %, 주식 수)를 0~1 자로 다시 재는 일입니다. 자의 눈금은 **훈련 데이터로만** 정해야 하고, 시험 데이터가 자 밖으로 나갈 수 있다는 점을 기억해야 합니다.
- **Concatenate**는 세 사람의 메모를 **옆으로 붙여** 한 장으로 만드는 일입니다. 더하거나 평균 내는 것이 아닙니다.
