## 주제

오늘은 LangGraph로 대화형 그래프를 만드는 기초를 학습했다.

1. `TypedDict`로 딕셔너리의 예상 형태를 적기
2. `Annotated[list, add_messages]`로 메시지 상태를 누적·병합하기
3. `StateGraph`의 상태, 노드, 엣지, 컴파일, 실행 흐름
4. `START`와 `END`를 사용한 그래프의 시작과 종료
5. 여러 노드를 `prepare → chatbot → finish` 순서로 연결하기
6. 환경변수에서 모델 연결 설정을 읽어 `ChatOpenAI`에 전달하기

## 중요한 내용

- `Dict[str, str]`와 `TypedDict`는 주로 사람이 코드를 이해하고 도구가 타입을 점검하도록 돕는 타입 힌트다. 일반적인 Python 실행에서 딕셔너리의 모든 값이 자동으로 강제 변환되지는 않는다.
- `Person(TypedDict)`는 `name`, `age`, `job`이라는 키와 예상 타입을 문서화한다. `Person(...)` 형태와 `Person` 타입으로 만든 딕셔너리 형태를 코드에서 모두 볼 수 있다.
- `Annotated`는 자료형에 추가 정보를 붙이는 문법이다. 여기서는 `messages`가 리스트이고, `add_messages`가 상태를 합치는 규칙이라는 뜻으로 사용된다.
- `add_messages(old, new)`는 메시지를 이어 붙이는 것과 비슷하지만, 같은 `id`를 가진 메시지가 들어오면 기존 메시지를 새 메시지로 교체한다. 따라서 단순한 `list.append`와 완전히 같지 않다.
- LangGraph의 상태는 그래프를 지나가는 공용 가방이다. 노드는 상태를 받아 필요한 상태 변경을 딕셔너리로 반환한다.
- 노드는 작업 함수이고, 엣지는 노드 사이의 이동 경로다. `START → chatbot → END`는 한 노드 그래프이고, `START → prepare → chatbot → finish → END`는 세 노드 순차 그래프다.
- `compile()`은 작성한 그래프 설계를 실행할 수 있는 형태로 만드는 단계다. 그 뒤 `invoke()`로 초기 상태를 넣어 실행한다.
- `("user", query)`는 LangChain 메시지로 변환되어 `messages` 상태에 들어간다. `add_messages`가 있으므로 chatbot 노드가 반환한 AI 메시지가 기존 사용자 메시지 뒤에 합쳐진다.
- 모델 호출은 환경변수의 API 키와 base URL, 외부 서비스, 설치된 패키지에 의존한다. 코드에 `temperature=0`을 주어도 모델 답변의 사실성까지 보장되는 것은 아니다.

## 반드시 기억할 점

- 타입 힌트는 설계도이지 자동 변환기가 아니다. `age`를 `int`로 적어도 문자열을 자동으로 숫자로 바꾸지는 않는다.
- 메시지의 `id`는 병합 결과에 영향을 준다. 서로 다른 ID이면 보통 둘 다 남지만, 같은 ID이면 새 메시지가 기존 메시지를 덮어쓴다.
- 그래프에서 노드를 추가하는 것만으로 실행 순서가 생기지 않는다. 엣지로 시작·다음 단계·종료를 연결해야 한다.
- `State`에 적은 필드와 실제 실행에 넣는 상태가 일치하는지 확인해야 한다. `TypedDict` 자체가 런타임에서 누락 키를 자동으로 채워 주지는 않는다.
- API 키는 코드에 직접 적거나 출력하지 않고 환경변수·비밀 저장소에서 읽어야 한다. 이번 문서에도 실제 credential 값은 기록하지 않았다.
- 코드의 주석 출력은 예상 예시일 수 있다. 오늘 실제 외부 모델 호출 결과나 네트워크 응답을 확인한 것으로 보지 않는다.

## 코드 흐름과 shape 설명

1. `lg01_TypedDict.py`에서 일반 딕셔너리와 `Person`이라는 TypedDict의 구조를 비교한다.
2. `lg02_add_messages.py`에서 `messages`를 리스트로 선언하고 `add_messages`로 두 메시지 리스트를 합친다. 서로 다른 ID인 `1`, `2`는 함께 남고, 같은 ID인 `3`은 뒤의 AI 메시지로 교체되는 예를 보여 준다.
3. `lg03_chatbot.py`에서 `State`를 정의하고, `chatbot(state)`가 현재 메시지들을 모델에 보내 AI 메시지를 반환한다. 그래프는 `START → chatbot → END`로 연결된다.
4. 실행 시 사용자 질문이 메시지 상태로 들어가고, chatbot 노드가 모델 응답을 추가한 뒤 결과 상태가 반환된다. 결과의 `messages`는 사용자 메시지와 AI 메시지를 담는 리스트로 생각할 수 있다.
5. `lg04_노드엣지추가.py`에서는 준비 안내를 반환하는 `prepare`, 모델을 호출하는 `chatbot`, 완료 안내를 반환하는 `finish`를 만들고 세 노드를 직렬로 연결한다.
6. `for i, msg in enumerate(response["messages"])`는 메시지 리스트의 순번과 내용을 함께 출력하려는 흐름이다. `enumerate`는 항목에 0부터 시작하는 번호를 붙여 준다.

예를 들어 메시지 두 개가 있으면 리스트의 모양은 개념적으로 `list[Message]`이고, 각 메시지는 `content`, `type`, `id` 같은 정보를 가진다. 실제 메시지 객체의 세부 필드는 사용하는 LangChain 버전과 실행 결과를 확인해야 한다.

## 쉬운 예시

그래프를 학교 심부름 길이라고 생각하자. `State`는 심부름 쪽지이고, 노드는 일을 하는 장소다. `prepare`에서는 “쪽지를 받았어요”라고 적고, `chatbot`에서는 질문을 선생님에게 전달해 답을 받으며, `finish`에서는 “일이 끝났어요”라고 적는다. 엣지는 장소 사이의 길이고 `START`는 출발점, `END`는 도착점이다. `add_messages`는 새 쪽지를 기존 쪽지와 합치는 규칙인데, 같은 번호의 쪽지가 오면 새 쪽지로 바꾼다.
