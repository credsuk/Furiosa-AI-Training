## 주제

오늘 새로 추가된 학습 코드는 없었다. 가장 최근 학습 코드인 RAG 예제의 실제 파일과 주석을 다시 읽고 다음을 복습했다.

1. PDF를 `Document` 목록으로 읽기
2. 문서를 작은 청크로 나누기
3. 임베딩으로 글을 숫자 벡터로 바꾸기
4. FAISS 저장소와 retriever로 관련 문서 찾기
5. `similarity_score_threshold`를 사용할 때 점수 의미 확인하기
6. 검색 결과를 프롬프트에 넣고 Gradio 대화 기록과 함께 LLM에 전달하기
7. BM25와 벡터 검색을 함께 사용하는 하이브리드 검색

## 중요한 내용

- `PyPDFLoader.load()`의 결과는 여러 `Document`를 담은 리스트다. 각 문서에는 본문 `page_content`와 출처 등의 `metadata`가 들어갈 수 있다.
- 청킹은 긴 문서를 검색하기 쉬운 조각으로 나누는 작업이다. `chunk_size=300`, `chunk_overlap=100`은 코드에 적힌 설정이며, 실제 생성 청크 수는 파일 내용과 splitter 동작을 실행해야 확인할 수 있다.
- 임베딩은 문장을 숫자 벡터로 바꾸는 과정이다. 문서와 질문을 같은 임베딩 공간으로 바꾸어 가까운 내용을 검색한다.
- FAISS의 인덱스 차원은 임베딩 벡터의 길이와 맞아야 한다. 코드의 `faiss_index.d`는 `embed_query("hello world")`의 길이로 정해진다.
- `k=2`는 보통 상위 2개 문서를 요청한다. 검색 결과가 항상 정확히 2개라는 뜻은 아니다. 특히 threshold 검색에서는 기준을 넘는 문서가 적으면 결과가 줄 수 있다.
- `similarity_score_threshold`의 점수 방향과 범위는 저장소·거리 설정에 따라 확인해야 한다. 주석의 `0.7`을 모든 벡터 검색기에 동일하게 적용하면 안 된다.
- `MessagesPlaceholder`와 `HumanMessage`·`AIMessage`는 이전 대화 내용을 이번 요청에 전달하는 장치다. 이것만으로 모델의 영구 기억이 생기지는 않는다.
- RAG는 검색 결과를 참고 자료로 제공할 뿐, 검색 결과의 품질과 모델의 답변이 자동으로 모두 보장되는 것은 아니다.

## 반드시 기억할 점

- 코드 주석의 `15`, `205`, `1536`, 임베딩 차원 등의 숫자는 실행 결과가 아닐 수 있다. 이번 환경에서는 PDF, FAISS DB, 로컬 임베딩 모델, 외부 API를 확인하지 못했으므로 사실로 단정하지 않는다.
- `FAISS.load_local(..., allow_dangerous_deserialization=True)`는 신뢰할 수 있는 파일만 불러오는 상황에서 사용해야 한다. 알 수 없는 파일을 역직렬화하면 위험할 수 있다.
- 여러 파일에서 PDF 파일명이 `Attention Is All You Need.pdf`와 `Attention_is_all_you_need.pdf`로 다르다. Linux에서는 공백·밑줄·대소문자가 다른 파일명이며, 실제 파일이 없으면 로딩 단계에서 실패한다.
- 환경변수에서 API 키를 읽는 코드는 키 값이나 일부를 출력하지 않아야 한다. 이번 정리에도 실제 credential 값은 기록하지 않았다.

## 코드 흐름과 shape 설명

1. PDF loader가 페이지마다 `Document`를 만든다. 결과의 자료형은 `list[Document]` 형태로 생각할 수 있다.
2. `RecursiveCharacterTextSplitter`가 각 문서를 여러 청크로 나눈다. 청크 하나는 문자열 본문과 metadata를 가진 `Document`다.
3. 임베딩 모델은 문서 청크와 질문을 각각 같은 길이의 벡터로 만든다. 여러 문서를 모으면 `(문서 수, 임베딩 차원)`처럼 생각할 수 있다.
4. FAISS는 벡터를 인덱스에 넣고 질문 벡터와 가까운 문서를 찾는다. `IndexFlatL2`를 만들 때의 `d`와 벡터 길이가 다르면 사용할 수 없다.
5. retriever는 검색된 `Document` 목록을 반환한다.
6. retrieval chain은 `context`, 대화 기록, 현재 `input`을 프롬프트에 넣고 모델의 답변을 만든다.
7. Gradio의 `history`를 순회하며 `user`는 `HumanMessage`, `assistant`는 `AIMessage`로 바꾼다.

예를 들어 벡터 1024개가 있고 각 벡터의 길이가 768이면 모양을 `(1024, 768)`이라고 표현할 수 있다. 하지만 코드의 실제 임베딩 차원과 문서 수는 모델·파일·실행 결과를 확인해야 한다.

## 쉬운 예시

도서관에 선생님에게 질문한다고 생각하자. 먼저 긴 책을 읽기 좋은 작은 종이 조각으로 나눈다. 질문과 종이 조각을 숫자 주소로 바꾸면, FAISS는 질문 주소와 가까운 종이를 찾는다. 찾은 종이를 선생님(LLM)에게 보여 주면 선생님은 그 자료를 참고해 답한다. BM25 사서는 질문에 나온 단어를 잘 찾고, 벡터 사서는 단어가 달라도 뜻이 비슷한 자료를 찾는 데 도움을 준다. 둘을 같이 쓰면 한쪽만 쓸 때보다 놓치는 자료를 줄일 수 있지만, 실제 답이 맞는지는 따로 확인해야 한다.
