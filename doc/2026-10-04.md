## 초보자용 설명

이번 복습은 데이터를 모델에 넣기 전 “자료의 모양과 의미가 맞는가”를 확인하는 연습입니다. NumPy의 `reshape`는 데이터를 새로 계산하지 않고 전체 원소를 다른 축으로 배열합니다. 따라서 `(batch, timestep, feature)`에서 각 축이 실제로 무엇을 뜻하는지 별도로 확인해야 합니다. pandas에서 `drop(..., axis=1)`은 예측 대상 열을 제거하며, scaler는 train 데이터에서 기준을 배운 뒤 test에는 같은 기준을 적용합니다. 분류에서는 label 표현(정수/one-hot), 마지막 activation, loss를 한 묶음으로 맞춰야 합니다.

## 핵심 기억

1. `reshape(-1, 2, 2)`의 `-1`은 전체 원소 수가 맞도록 자동 계산되는 한 축입니다.
2. `input_shape=(timestep, feature)`에는 batch 크기를 넣지 않습니다.
3. `Reshape`는 원소 수를 보존하지만 timestep의 의미를 자동으로 판단하지 않습니다.
4. 시계열 평가는 미래 정보를 과거 학습에 섞지 않도록 시간 순서를 보존합니다.
5. 코드 주석의 예상 shape나 과거 실행 결과는 현재 실행 결과와 동일하다고 가정하지 않습니다.

## Shape 기록

- MNIST 원본 `(60000, 28, 28)` → CNN 입력 `(60000, 28, 28, 1)`
- Kaggle bike의 8개 feature → `(batch, 4, 2)`
- CNN 중간 결과 `(batch, 23, 23, 16)` → `Reshape((529, 16))` → `(batch, 529, 16)`
- `LSTM(10)`은 입력의 timestep·feature를 처리한 뒤 기본적으로 각 샘플의 출력 하나를 내므로 출력은 일반적으로 `(batch, 10)` 형태입니다. 실제 실행 결과는 이 작업에서 확인하지 않았습니다.
