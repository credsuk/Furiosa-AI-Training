## 1. `include_top`이 자르는 것

`include_top`은 "맨 위(top)의 분류기까지 가져올까?"를 정하는 스위치입니다.

```python
VGG16(weights='imagenet', include_top=True)    # 합성곱 13층 + Dense 3층(4096-4096-1000)
VGG16(weights='imagenet', include_top=False,
      input_shape=(32, 32, 3))                 # 합성곱 13층까지만
```

**실측 (이 환경):**

| 설정 | 전체 파라미터 | `len(model.weights)` | 출력 |
|---|---|---|---|
| `include_top=True` (기본 224×224) | 138,357,544 | 32 | `(None, 1000)` |
| `include_top=False`, 입력 32×32 | 14,714,688 | 26 | `(None, 1, 1, 512)` |

- 138,357,544에서 14,714,688을 빼면 123,642,856개가 사라집니다. 이것이 `fc1`(102,764,544) + `fc2`(16,781,312) + `predictions`(4,097,000)입니다.
- `include_top=False`로 자르면 **입력 크기를 내 데이터에 맞게 바꿀 수 있습니다.** 우리는 32×32 CIFAR를 그대로 넣습니다.

## 2. "가중치 26개"의 정체

`weights`는 "무게 값 덩어리"이고, 층 하나가 보통 **커널(가중치) 1개 + 편향 1개**를 가집니다.

- 합성곱 층 13개 × 2 = **26개** (실측 `len(v.weights) == 26`, `Conv2D` 층도 13개)
- `include_top=True`면 Dense 3개 × 2 = 6개가 더 붙어 **32개** (실측)
- `keras74_1`처럼 뒤에 `Dense(100)`, `Dense(10)`을 붙이면 26 + 2 + 2 = **30개** (실측 `len(model.weights) == 30`)

그런데 `keras74_1_layers.py`의 주석은 이렇게 적혀 있습니다.

```python
print(len(model.weights)) # 30 = 16(vgg16) * 2 (w, b) + 2 (dense) + b
```

- **16 × 2 = 32가 아니라 13 × 2 = 26입니다.** VGG16의 "16"은 가중치를 가진 층이 16개(합성곱 13 + Dense 3)라는 뜻이고, `include_top=False`로 Dense 3개를 잘라냈으니 13개만 남습니다.
- 그래서 맞는 식은 `26 + 2 + 2 = 30`입니다. 결과 숫자 30은 맞지만 **식을 잘못 적은 주석**입니다.

## 3. `include_top=True`는 왜 입력을 못 바꾸나

`include_top=True`의 Dense 층은 "7×7×512를 펴서 25,088개"라는 **고정된 크기**를 전제로 만들어진다. 입력이 32×32면 특징 맵이 1×1×512가 되어 25,088이 나오지 않습니다.

```python
VGG16(weights='imagenet', include_top=True, input_shape=(32, 32, 3))
```

**실측 오류 메시지:**

```
ValueError: When setting `include_top=True` and loading `imagenet` weights,
`input_shape` should be (224, 224, 3).  Received: input_shape=(32, 32, 3)
```

즉 케라스가 "그 조합은 안 된다"고 미리 막아 줍니다. 내 이미지 크기를 쓰고 싶으면 `include_top=False`가 정답입니다.

## 4. `trainable = False`는 어디까지 잠그는가 — 오늘의 가장 중요한 발견

`keras74_1`은 이렇게 씁니다.

```python
vgg16 = VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))
vgg16.trainable = False        # VGG16 전체를 잠근다
model = Sequential([vgg16, Flatten(), Dense(100), Dense(10, activation='softmax')])
```

여기까지는 문제가 없습니다. 실측으로 `len(model.trainable_weights) == 4` (Dense 2개 × 커널/편향)입니다.

그런데 **나중에 상위 모델에 `model.trainable = True`를 실행하면 어떻게 될까요?** "새로 붙인 Dense만 풀릴 것 같지만" 실제로는 **이미 잠가 둔 VGG16까지 전부 다시 열립니다.**

**실측 (VGG16 하나만):**

| 코드 | `len(trainable_weights)` | 안쪽 층의 `trainable` |
|---|---|---|
| 처음 | 26 | 전부 True |
| `layers[1].trainable = False` | 24 | 1번만 False |
| `model.trainable = False` | 0 | **모든 층 False로 전파** |
| `model.trainable = True` | **26** | **모든 층 True로 전파 (1번도 풀림)** |

**실측 (Sequential 안에 넣은 경우):**

```python
v = VGG16(include_top=False, input_shape=(32,32,3)); v.trainable = False
seq = Sequential([v, Flatten(), Dense(10, activation='softmax')])
# len(seq.trainable_weights) == 2   (Dense 것만)
seq.trainable = True
# len(seq.trainable_weights) == 28  (Dense 2 + VGG16 26) ← 동결이 풀렸다
```

- 왜 이게 위험한가: 배치 정규화 층이나 앞단 특징이 학습 데이터에 맞춰 **망가질 수 있고**, 학습 시간도 몇 배로 늘어납니다. `keras73`의 "동결X" 실행이 정확도 `0.1`(10클래스니까 찍기)로 끝난 것도 이 경우입니다. 손실 `2.3028`은 `ln(10) = 2.3026`과 거의 같아서, "10개 중 하나를 공평하게 찍는 상태"를 그대로 보여 줍니다.
- 안전한 순서: **① 백본 동결 → ② 내 분류기 학습 → ③ (필요하면) 백본 일부 해제 → ④ `compile()` 다시 → ⑤ 낮은 학습률로 미세 조정.** ③에서 상위 모델의 `trainable`을 건드리면 ①이 무효가 될 수 있으니, 해제는 **층 하나씩**(`vgg16.layers[i].trainable = False/True`) 다루는 편이 안전합니다.

## 5. `model.layers[2]`는 `Flatten`이 아니다

`keras74_3_layers_부분동결.py`:

```python
model.add(vgg16)          # layers[0]
model.add(Flatten())      # layers[1]
model.add(Dense(100))     # layers[2]  ← 여기!
model.add(Dense(100))     # layers[3]
model.add(Dense(100))     # layers[4]
model.add(Dense(100, trainable=False))  # layers[5]
model.add(Dense(10, activation='softmax'))  # layers[6]

model.layers[2].trainable = False   # 주석: "Flatten도 쳐준다"
```

**실측한 층 목록:**

```
[('Functional','vgg16',False), ('Flatten','flatten',True), ('Dense','dense',True),
 ('Dense','dense_1',True), ('Dense','dense_2',True), ('Dense','dense_3',False),
 ('Dense','dense_4',True)]
```

- `layers[2]`는 **`dense`(첫 번째 Dense)** 입니다. Flatten은 `layers[1]`입니다. 즉 주석 "Flatten도 쳐준다"는 **층 번호를 잘못 짚은 설명**입니다.
- `layers[2].trainable = False`를 실행하면 `dense`가 False로 바뀌고, `len(model.trainable_weights)`는 **6**(`dense_1`, `dense_2`, `dense_4`의 커널/편향)이 됩니다. 전체 가중치는 36개, 총 파라미터는 14,797,298개(실측)입니다.
- 파일 아래쪽 주석의 표는 `dense`(2번)와 `dense_3`(5번)를 **True**로 적고 있는데, 실제로는 둘 다 **False**입니다. 주석 표를 그대로 믿으면 "동결이 안 됐다"고 착각합니다.
- 교훈: 층을 번호로 집을 때는 **`model.layers[i].name`을 반드시 같이 찍어서** 확인한다. 번호는 층을 하나 추가할 때마다 통째로 밀립니다.

## 6. `keras74_4`의 `layers[0]`은 `InputLayer`

```python
model = VGG16(weights='imagenet', include_top=False, input_shape=(32,32,3))
model.layers[0].trainable = False
```

**실측:**

- `layers[0]`의 타입은 `InputLayer`, 가중치는 **0개**. 그래서 `trainable=False`를 해도 `len(trainable_weights)`는 26에서 **26 그대로**입니다. (아무 일도 일어나지 않음)
- `layers[1]`(첫 `Conv2D`)을 잠그면 26 → **24**로 줄어듭니다.
- 이어서 `model.trainable = True`를 실행하면 **26으로 되돌아옵니다**(4번에서 본 전파 때문). 즉 "잠갔다가 다시 열었다"가 됩니다.

## 7. `Dense(1, sigmoid)` + `sparse_categorical_crossentropy`는 실행 중에 터진다

`keras76_all_T_3_man_hores.py`는 말/사람 이진 분류인데 이렇게 조합했습니다.

```python
model.add(Dense(1, activation='sigmoid'))                      # 출력 1개(0~1 확률)
model.compile(loss='sparse_categorical_crossentropy', ...)     # 클래스 여러 개용 손실
```

- `sparse_categorical_crossentropy`는 "정답 번호가 `0 ~ 클래스수-1` 사이에 있어야 한다"고 가정합니다. 출력이 1개면 클래스수는 1로 해석되어 **허용 범위가 `[0, 1)`**, 즉 정답은 0만 가능합니다.
- 정답에 1이 들어오는 순간 **실측 오류**:

```
InvalidArgumentError: Graph execution error:
Received a label value of 1 which is outside the valid range of [0, 1).
```

**고치는 방법(둘 중 하나):**

- `Dense(1, activation='sigmoid')` + `loss='binary_crossentropy'` (정답은 0/1)
- `Dense(2, activation='softmax')` + `loss='sparse_categorical_crossentropy'` (정답은 0/1, 클래스 2개)

또 이 파일은 `train_test_split(..., train_size=0.2)`이라 **학습 20% / 시험 80%** 로 나뉩니다. 보통은 반대(학습 80%)입니다.

## 8. 32×32 입력에서 특징 맵은 `(1, 1, C)`가 된다

VGG16은 풀링을 5번 합니다(32 → 16 → 8 → 4 → 2 → 1). 그래서 32×32 사진은 마지막에 **가로·세로가 1칸**만 남습니다.

**실측 (모두 `include_top=False`, 입력 32×32):**

| 백본 | 출력 모양 | 파라미터 |
|---|---|---|
| VGG19 | `(None, 1, 1, 512)` | 20,024,384 |
| ResNet50 | `(None, 1, 1, 2048)` | 23,587,712 |
| ResNet101 | `(None, 1, 1, 2048)` | 42,658,176 |
| DenseNet201 | `(None, 1, 1, 1920)` | 18,321,984 |
| MobileNetV2 | `(None, 1, 1, 1280)` | 2,257,984 |
| EfficientNetB0 | `(None, 1, 1, 1280)` | 4,049,571 |

- `(1,1,512)`를 `Flatten`하면 `(None, 512)`, `GlobalAveragePooling2D`도 `(None, 512)` — **32×32에서는 둘의 결과가 같습니다.**
- 차이는 입력이 클 때 드러납니다. 224×224에서 VGG16은 `7×7×512` = **25,088** → `Dense(100)`의 파라미터가 `25,088×100+100 = 2,508,900`개. `GAP`를 쓰면 `512×100+100 = 51,300`개. **약 49배 차이**입니다.
- `keras74_1`의 `Flatten` 출력이 `(None, 512)`인 이유도 이것입니다(실측). "Flatten을 쓰면 파라미터가 늘어난다"는 말은 **입력이 충분히 클 때** 맞는 말입니다.

## 9. `trainable`을 바꾼 뒤에는 `compile()`을 다시 해야 한다

**실측 (Dense 두 층짜리 작은 모델, 같은 데이터·같은 3 epoch):**

| 순서 | 학습 후 첫 Dense 커널의 최대 변화 |
|---|---|
| 동결 → `compile` → **재컴파일 없이** `trainable=True` → `fit` | **0.0** (전혀 안 바뀜) |
| 동결 → `compile` → `trainable=True` → **`compile` 다시** → `fit` | **0.0879** (바뀜) |

- 이유: `compile()`은 "어떤 가중치를 업데이트할지" 목록을 그 순간에 만들어 둡니다. 그 뒤에 `trainable`을 바꿔도 이미 만들어진 학습 목록은 그대로입니다.
- 그래서 "동결을 풀었다"고 생각했는데 실제로는 안 배우는 사고가 생깁니다. **`trainable`을 바꾼 직후 `compile()`을 다시** 하세요.

## 10. `keras75`의 "전체 236 / 학습 가능 156" — 동결이 아니라 구조

`keras75_ALL_TransferLearning.py`는 여러 모델을 만들어 `len(model.weights)`와 `len(model.trainable_weights)`를 찍고 마지막에 "기본적으로 동결되어 있는 가중치가 많다"고 적었습니다.

**실측 (Xception):**

- `len(weights) = 236`, `len(trainable_weights) = 156` → 차이 **80**
- BatchNormalization 층이 **40개**, 그 각각이 `moving_mean`, `moving_variance` 2개씩 = **80개**
- 40개 BN 층의 `trainable` 플래그는 모두 **True**였습니다.

즉 80개는 "잠근 가중치"가 아니라 **평균·분산 같은 통계량**이라 원래부터 학습 대상이 아닙니다. "동결되어 있다"는 표현은 정확하지 않고, **"학습되지 않는 가중치(통계량)가 들어 있다"** 가 맞습니다.

또 `keras75`는 `VGG16()`, `ResNet50()`처럼 **인자 없이** 불러서 `include_top=True`(224 입력) 기본값입니다. 그래서 같은 백본을 `include_top=False`로 만든 내 실측과 개수가 2개씩 다릅니다(마지막 `fc`의 커널+편향).

| 모델 | `keras75` 주석(기본값, top 포함) | 내 실측(`include_top=False`) |
|---|---|---|
| VGG16 | 32 | 26 |
| VGG19 | 38 | 32 |
| ResNet50 | 320 | 318 |
| DenseNet201 | 1006 | 1004 |
| MobileNetV2 | 262 | 260 |
| EfficientNetB0 | 314 | 312 |

## 11. `keras76` 묶음에서 눈에 띄는 것

- `keras76_all_T_1_cifar10.py`는 **반복문 안에서** `cifar10.load_data()`를 부릅니다(모델 6개 → 6번). `keras76_all_T_2_cifar100.py`는 반복문 **밖에서 한 번** 부릅니다. 같은 결과지만 앞의 코드는 매번 170MB를 다시 읽습니다.
- `keras76_all_T_3_man_hores.py`의 sigmoid + sparse 손실 조합은 7번에서 본 오류로 **학습이 시작되지 않습니다.**
- `keras76_all_T_5_man_woman.py`는 목록에 `InceptionV3()`, `InceptionResNetV2()`를 **인자 없이** 넣어 299×299 입력(1000 클래스 분류기 포함)을 그대로 씁니다. 다른 모델은 `include_top=False`인데 이 둘만 다릅니다.

## 반드시 기억할 점

- `include_top=False`는 분류기를 자르는 것이고, **가중치를 잠그는 것은 아니다.** 잠그려면 `trainable=False`를 따로 써야 한다.
- VGG16의 가중치 26개 = **합성곱 13층 × (커널, 편향)**. "16 × 2"가 아니다.
- `include_top=True` + `imagenet` + 32×32 조합은 **오류**다. 내 이미지 크기를 쓰려면 `include_top=False`.
- 상위 모델의 `model.trainable = True`는 **안쪽 백본까지 다시 학습 가능하게 만든다.** 동결은 가장 바깥에서 조심해서 다룬다.
- 층 번호(`layers[2]`)로 동결하지 말고 **`layers[i].name`을 찍어 확인**한다.
- `trainable`을 바꾼 뒤에는 **`compile()`을 다시** 한다. 안 하면 가중치가 0.0만큼도 안 움직인다.
- 32×32 입력에서는 특징 맵이 `(1,1,C)`라서 `Flatten`과 `GAP`의 결과가 같다. 차이는 **입력이 클 때** 생긴다.
- `Dense(1, sigmoid)`에는 `binary_crossentropy`, `Dense(N, softmax)`에는 `sparse_categorical_crossentropy`(정수 정답) 또는 `categorical_crossentropy`(원-핫 정답).
- `len(weights)`와 `len(trainable_weights)`의 차이는 "동결"뿐 아니라 **BN 통계량** 때문에도 생긴다.

## 쉬운 예시

**예시 1 — 자르기와 잠그기의 차이**

이미 잘 훈련된 요리사(VGG16)를 빌렸다고 생각해 봅시다.

- `include_top=False` = 요리사의 **최종 플레이팅 담당(분류기)을 보내고**, 재료 손질 실력(특징 추출)만 빌리는 것.
- `trainable=False` = 빌린 요리사에게 **"오늘은 손질법을 바꾸지 마"** 라고 잠그는 것.

둘은 다른 일입니다. 손질 담당을 보냈다고 해서 남은 사람이 자동으로 잠기는 게 아닙니다. 그리고 매니저(상위 모델)가 "전원 새 기술 배우자(`model.trainable=True`)"고 하면 **잠가 둔 요리사도 다시 배우기 시작합니다.**

**예시 2 — 32×32 사진이 1×1이 되는 이유**

32→16→8→4→2→1. 반으로 접기를 5번 하면 32는 1이 됩니다. 그래서 "가로·세로 1칸 × 채널 512개"만 남습니다. 이 상태에서는 `Flatten`(펴기)과 `GAP`(평균 내기)가 **둘 다 512개 숫자**를 만듭니다. 사진이 224×224라면 마지막이 7×7이라 펴면 25,088개, 평균 내면 512개로 크게 벌어집니다.

**예시 3 — 손실 함수는 "정답의 생김새"와 짝이 맞아야 한다**

- 출력이 확률 1개(`sigmoid`)면 정답은 "0 또는 1" 두 갈래 → `binary_crossentropy`.
- 출력이 확률 N개(`softmax`)면 정답은 "0~N-1 중 하나" → `sparse_categorical_crossentropy`.

`Dense(1, sigmoid)`에 N개용 손실을 붙이면, 케라스는 "클래스가 1개뿐"이라고 이해해서 정답 1을 **범위 밖 숫자**로 봅니다. 그래서 `outside the valid range of [0, 1)` 오류가 납니다.

## 검증 범위 및 미확인

**실제로 실행해 확인한 것 (이 환경):**

1. `VGG16(include_top=False, 32×32)`: params 14,714,688, weights 26, `Conv2D` 13개, 출력 `(None,1,1,512)`, `trainable=False` 후 trainable weights 0
2. `VGG16(include_top=True)` 기본: params 138,357,544, weights 32, 출력 `(None,1000)`
3. `include_top=True` + 32×32 + imagenet → `ValueError ... input_shape should be (224, 224, 3)`
4. `keras74_1` 재현: 총 14,766,998개, weights 30, trainable weights 4, 학습 대상 52,310개, Flatten 출력 `(None,512)`
5. 동결 전파: 26 → 24(층 하나) → 0(모델) → 26(모델 True, 자식까지 복원), Sequential 안 백본도 `seq.trainable=True`에 28로 풀림

7. `keras74_4` 재현: `layers[0]`=`InputLayer`(가중치 0) → 26 그대로, `layers[1]` → 24, `model.trainable=True` → 26
8. 재컴파일 실험: 재컴파일 없이 해제 → 커널 최대 변화 0.0, 재컴파일 후 → 0.0879
