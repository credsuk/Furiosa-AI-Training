## 이날의 주제: validation과 과적합 관찰

validation_split·validation_data, 학습 시간, history와 loss 곡선, 여러 데이터셋에서의 과적합을 확인했습니다.

## 반드시 기억할 내용

train loss만 낮아지는 것은 충분하지 않습니다. validation loss가 올라가면 일반화가 나빠지는 과적합 신호입니다.

```text
train loss ↓ + validation loss ↑ = 과적합 의심
```

## 학습 보강: validation과 과적합

### Python 문법 반복

`history = model.fit(...)`처럼 함수 반환 객체를 저장하면 이후 `history.history['loss']`처럼 내부 기록에 접근할 수 있습니다. 딕셔너리에서 키로 값을 꺼내는 문법을 반복합니다.

### NumPy 핵심

학습 기록은 배열 또는 리스트 형태로 다뤄질 수 있습니다. `np.argmin(val_loss)`는 validation loss가 가장 작은 위치를 찾는 함수이며, 최솟값 자체가 아니라 인덱스를 반환한다는 점을 구분합니다.

### pandas 확인

이날 문서의 핵심은 Keras validation과 history이며 pandas 직접 사용은 확인되지 않았습니다. 표 형식 로그를 pandas로 만들 때도 train과 validation 열을 섞지 않고 각각 확인합니다.

### 반복해서 기억할 점

`validation_split`은 학습 데이터 일부를 validation으로 떼는 것이고 test를 대체하지 않습니다. train loss 감소만으로 학습이 잘됐다고 결론내리지 말고 두 곡선의 방향을 함께 봅니다.
